## Strategy in one paragraph

An audiophile player lives or dies on **library + playback maturity, not on its cleverest DSP** — a listener who can't get an album into a queue never hears the differentiator. So we **reach competitive parity as a player first** (Phase 1), then build the differentiating *Adaptive Sound* thesis — masking-aware perceptual clarity, one Intensity knob over the automatic stages, spatial rendering — on top of a credible base where it can actually be compared against the field (Phase 2). Our anchor story is *this Mac → this DAC, bit-perfect* (which Apple Music is not, on macOS). See [../sprints/sprint-plan.md](../sprints/sprint-plan.md) §1.

**After R1 (founder, 2026-10-14):** make the default experience faithful, durable and honest first (R1.1), then build our own playback engine in a sprint of its own, then ship the R2 features, each carrying only the restructuring it needs. No standalone refactor waves (FD-1).

**The sound (founder, 2026-10-23):** every choice about the sound features is ranked by how good the end product sounds to a listener, not by cost or delivery date. A fresh launch plays the file as recorded; level has one owner and tone one program; every processing stage proves itself on the founder's own blind, level-matched A/B at the end of its sprint or ships off and hidden; and every control says, in words, when an output can't do it. The model is in [The sound plan](#the-sound-plan-decided-2026-10-23).

## The post-R1 plan (council, 2026-10-14)

**Recommendation, adopted by the founder:** fix what the listener hears and loses first; then replace the Enhanced engine's internals with our own engine, measured against a mature one; then features.

```
R1 (shipped) → R1.1-A → test-rig redesign → R1.1-B → Engine sprint → R2: S14-lite → S12 → S13 → S11-lite → R3: S15 → S16 → S17 (S18 last)
                                  (R1.1 is the daily driver)   each R2 sprint carries its own structural slice
W2's engine half: the Engine sprint · W2's transport half: S15 · EP-MCP: a consumer of S15's command layer, R2 or later (FD-8, amended 2026-10-23)
```

Why this order, in short (detail in the [council report §6](../reviews/2026-10-council/README.md#6-the-plan)):
- **R1.1 first (FD-1).** A fresh launch plays processed sound, Master Gain comes back at its loudest, and dragging the scrubber to the end of a 44.1 kHz track stops the music. Each is small, and each is something the founder meets every day.
- **The Engine sprint next (FD-4).** The Enhanced path's gaps, clicks, early title changes and seek hang share one root: it hands its queue to `AVAudioPlayerNode` and re-derives position from callbacks (council RC-2). The founder chose to study SFBAudioEngine, build our own engine with that knowledge, and compare the two before deciding.
- **R2 in the product's order.** S14 is the cheapest proof of "adaptive"; S12 and S13 are table stakes for enthusiasts; S11 is format breadth, which matters least for the founder's own library.

### The sound plan (decided 2026-10-23)

The decided model for every sound feature from R1.1-B on, stated once. The sprint rows below name only their own deliverables and point here for the model. Rationale, the options rejected and the evidence: [roadmap reconciliation — README](roadmap-reconciliation-2026-10/README.md) ("Decisions taken", cards 1–12) and its [sound pass](roadmap-reconciliation-2026-10/brainstorm/quality-pass-sound.md). Words: *the processed mode* = Enhanced; *the bit-perfect mode* = Pure; *the net* = the true-peak limiter, the last stage of the engine; *the ceiling* = how close to full scale the net lets true peaks go; *the turn-down* = the peak-safe pre-gain; *the ledger* = the one place that adds up every gain request.

**The chain, in order (the processed mode).** Decoder → one owner of the channel layout from the decoder onward (Engine sprint) → **the level stage**: one broadband gain per track — leveling plus the peak-safe turn-down — applied once, before the EQ → **the one EQ program** (correction | taste | compensation, one filter set) → **the fold** (surround → stereo; interim: in the spatial unit after the net, final: inside the engine before the headphones stage and the net — the Engine sprint's design fixes where it sits relative to the program) → **the headphones stage** (Off / Crossfeed / Spatial, at the engine's stereo-out slot) → **the one net** (last; metered; expected to sleep) → the engine ends → Master Gain (turn-down only; the engine never knows where it sits) → the output. The automatic stages (Clarity in S16; room amount in S18) are *settings inside* the program and the render, not a parallel path: there is no wet/dry blend anywhere.

1. **Level has one owner.** Each track's level is set once, before it starts, and nothing moves it inside a song — except the listener's own act: a Leveling mode change mid-song applies at once with a short glide; automatic changes never move inside a song (founder, 2026-10-25).
   - **Leveling:** Off / Auto / Album / Track, off by default. One fixed gain per track or album through the existing per-track gain owner; the old auto-leveller is *removed* from the code, not switched off. Target **−18 LUFS** (every album can reach it under the true-peak cap; it is shown next to the setting). Our own analysis first; file tags (ReplayGain / R128) only for a track not yet analysed; a fixed **−5 dB** cut for a track of unknown loudness — never a live estimate. Auto = the album gain when the neighbouring track — the one just played or the next — is from the same album, else the track gain; a gapless album takes the album gain even in Track mode. The gain is capped by the track's true peak (the analysis gains a true-peak number) so the net stays asleep. *Decided as recommended (founder, 2026-10-25):* the analysis persists in a rebuildable derived-data file beside the library, keyed by file identity — never in the library DB; an album's tracks are analysed in the background once any of its tracks is queued; no library-wide sweep in R1.1-B. Album mode on an album not yet fully analysed: the album's tags if every track has them, otherwise the track plays at its own gain and the album gain starts at the next seam across silence — the level never steps at a continuous seam. The Leveling row lives in **Settings** (founder, 2026-10-25).
   - **The peak-safe turn-down:** three numbers per track, all from the same analysis — `g` = the leveling gain (capped so that true peak + g ≤ C_work); `−ΔL` = the taste layer's loudness-neutral offset (exists today); `C_cap` = C_work − (track true peak + g + B), where B = the program's biggest boost and **C_work = the limiter's working ceiling = the ceiling − 0.27 dB** (its working margin; defined once in the [backlog's numbers](backlog.md#the-numbers-one-set-a-story-may-only-cite-these)). The peak *after* leveling is what is protected, and C_cap may be positive — it is a cap, never clamped to 0. The published broadband offset beyond leveling is **G = min(−ΔL, C_cap)** and the turn-down shown to the listener is **T = G − (−ΔL) ≤ 0** ("−3 dB to protect the sound"), applied once before the EQ so the net never has to work; the compensation layer is exempt from −ΔL (its level change is read, not neutralised). R1.1-B bounds B by the curve's biggest boost; S14-lite's ledger measures the EQ'd track's real peak instead (it turns down less on most tracks).
   - **The bit-perfect mode — deferred until the USB DAC arrives** *(amended 2026-10-25: Pure declines Bluetooth, so the XM4 always plays Enhanced — the premise that Pure is the founder's daily mode was wrong; leveling in Pure is deferred until the USB DAC arrives, verified there.)* Until then the Leveling row in Pure shows the shared "Not in bit-perfect mode" state ("Leveling off (bit-perfect)"). The design it lands with, with or after the USB-DAC check (FD-5's parked list): leveling rides the device's own volume through the volume loan — cut-only, in the device's steps, set at the seam, the loan taught to tell its own moves from the listener's; the stream is never touched. The soundbar (no volume the Mac can set) is excluded and told. ~~When Pure hands the volume back, a "Volume restored" toast.~~ The "Volume restored" toast is not leveling's: it belongs to Master Gain's existing loan and ships in R1.1-B (§10).
   - **The ceiling:** **−1 dB** true peak on Bluetooth and on any output whose rate is not the engine's 48 kHz, until the Engine sprint measures the output-side conversion; **−0.1 dB** only where the link is lossless *and* the rate matches (the HDMI soundbar, a 48 kHz DAC), on the EQ-only path as Sprint EQ decision 29 set it — decision 29 is scoped, not reversed. With the turn-down the net is expected to sleep at either ceiling.
   - **The ledger (S14-lite):** the per-band sum of the EQ layers held at **+12 dB** (proportional scaling); one turn-down applied once; AutoEq's "Preamp:" line replaced by the ledger; the net's gain reduction metered and shown; the graph says it *protected* the sound where the sum was held, never that it refused. Two numbers, never conflated: the loudness offset (−ΔL, exists) and the peak-safe cap C_cap; the published broadband offset is G = min(−ΔL, C_cap) and the turn-down shown is T = G − (−ΔL) — the form of §1's turn-down bullet.
2. **Tone has one program.** Ordered layers **correction | taste (the 31 points, Tone, parametric bands) | compensation** → one design step → one set of filters, drawn as they play (one composed read-back), a bypass per layer. **Compare** keeps one meaning — "without *my* EQ"; correction and compensation stay — and is level-matched within **0.2 dB** over every offset the program adds, the turn-down included. A separate latching **"Bypass all processing"** gives the file. The existing per-output memory is the only per-device memory, extended with the parametric bands and the correction choice. S16's Clarity emits into this program; there is never a second filter engine. The EQ preset "Clarity" is displayed as **"Detail"** (stored id unchanged) before S15.
3. **Low volume keeps its bass (the loudness button, S14-lite).** Level = Master Gain + the device's own volume where the Mac can read it, against a one-time reference ("this is my normal loud setting"); a labelled manual **"Loudness amount"** on an output whose volume the Mac cannot read (the soundbar over HDMI). The level reading includes everything that changes the level at the ear — leveling's gain and the turn-down too. The curve is the **ISO 226 difference, bass only** — for a 20 dB turn-down the full difference is about **+10.5 dB at 20 Hz, +8.2 at 50 Hz, +6.2 at 100 Hz, +3.9 at 200 Hz, +1.2 at 500 Hz, ~0 from 1 to 8 kHz**; nothing above 1 kHz is applied (the treble lift the old stories planned would add fizz); for a 10 dB turn-down about half. Depth: **start at 50 %** of the difference (+3 dB at 100 Hz, +4 at 50 Hz, +5 at 20 Hz for a 20 dB turn-down), **cap +6 dB** in the bass; the depth is open until the one-evening prototype on the XM4 (40 / 50 / 60 % at a 20 dB turn-down on three familiar loud masters), decided by the founder's ear, 50 % until then. Form: **ease the mids, never boost** (the curve shifted down by its own maximum, so the net never wakes), with the level read as "volume minus its own cut" so there is no loop. The caption says "nudge the volume up a notch". One "Level" card with plain names — "Even out track levels", "Keep bass at low volume" — and a net-gain readout, built in Settings, where the Leveling row lives (founder, 2026-10-25), unless the founder decides otherwise at S14-lite. Not in the bit-perfect mode, and it says so. One check owed: whether the XM4's own buttons move the Mac's volume slider — open until the founder checks (a minute on the XM4); if they don't, the caption says "use the Mac's keys".
4. **Headphones have one control:** **Off / Crossfeed / Spatial**, exclusive by construction, remembered per output. Correction stays before the render; the render's responses are headphone-equalised so Spatial changes space, not tone; room amount is a setting Intensity scales, never a wet/dry blend; head tracking opt-in. Until S18 the control is the crossfeed switch; on a folded surround file crossfeed does nothing until the fold moves inside the engine, and the chip says so (it reads the engine's bypass, so "XF" never shows when nothing plays).
5. **Surround folds once, before the one net.** The ITU-R BS.775 matrix; channel roles from the file's labels first; a per-track trim from the folded true peak so the net is a backstop that stays asleep; the folded loudness measured in the same pass so leveling is exact; **the LFE decided per track from the analysis** — include at full level per side when it carries bass the mains do not, omit when it is a low-passed copy of the mains' bass, omit when unknown; the trim computed with that LFE gain; a **"5.1 → stereo"** badge; the bit-perfect reason reads "…so Enhanced plays it, folded to stereo". *Interim (R1.1-B):* the matrix and the trim in today's spatial unit, with a backstop after it that the trim keeps asleep. *Final (Engine sprint):* inside the engine before the headphones stage and the one net, one layout owner from the decoder onward. S18 renders at the same stereo-out slot.
6. **The automatic stages and Intensity (S16, S17).** Clarity depth and room amount are settings inside their stages; Intensity scales only those two, as settings — never a crossfade, never a level change, never a switch the listener set. 0 = nothing automatic; hand-set stages still play. Default 0. Both settings stay visible on their own rows. Clarity has its own on/off, depth and chip from S16.
7. **Enhance.** One switch per output that turns on, together, the stages that won their blind test on that output, with a chip that names what it did in the listener's words ("Enhance: even levels · full at low volume"); holding the chip plays the file without it at matched loudness; a level change made by design is stated ("−6 dB to match your other albums"); in the bit-perfect mode one honest line and one tap out ("Not in bit-perfect mode — leave Pure?"); never "ENHANCED" alone; never a stage that lost; never Loudness before its reference is set. Off returns the file as recorded.
8. **Correction and Spatial are offered, never applied.** Opt-in per device, off on a fresh install; "auto-load" means *offer with a level-matched hold-to-hear preview, and remember*; the device class only picks the default suggestion for a never-seen output; a status-badge entry for every stage that plays.
9. **The blind-test rule.** The last acceptance line of each processing sprint — **S14-lite, S16, S18** — is the founder's blind, level-matched A/B on their own gear (the XM4 and the soundbar): the [adaptive-tone ladder](../design/adaptive-tone/README.md#6-how-we-would-prove-it-the-evaluation-ladder), about **23 trials, capped at 60**, matched within **0.2 dB** over every offset the engine adds. Bar: "can't tell" for anything that plays by default; "prefer" for anything Enhance turns on. Loudness is tested at the real late-night level with the reference set ("with" vs "without, nudged to equal loudness"); Clarity against the static "Detail" preset, then the original; Spatial against a timbre-matched dry reference (same correction, headphone-equalised responses) with an artifact checklist — no smeared centre, no hollow tone, bass intact; "I can tell them apart" proves nothing. A stage that does not win ships off and hidden. No pre-sprint tests (founder, card 10 ≠ R). Leveling is not judged by the A/B — a constant gain per track is level-matched by definition — but by its own measurements (consistency: the oracle, the sleeping net); it may be part of Enhance as "even levels".
10. **Faithful by default; honest everywhere.** A fresh launch plays the file as recorded (the bit-exact anchor at Intensity 0 with nothing on survives every sprint: every stage is opt-in). The app never claims bit-perfect when it isn't. Every DSP control carries the shared **"Not in bit-perfect mode"** row state (first instance R1.1-B) and the Pure badge lists what is skipped; when Pure hands back the device volume Master Gain lowered, a **"Volume restored"** toast says so (R1.1-B — Master Gain's existing loan, not leveling's); the Pure card says in one sentence why there are two "untouched" states (Pure, and Enhanced with nothing on).

### The Engine sprint

**Goal:** one owner of the Enhanced audio timeline, written by us with the knowledge of a mature open-source engine, and proven better — or not — by measurement before it ships. **Placed after R1.1 and before R2** (FD-4). It is the founder's one named exception to FD-1's "no standalone refactor": a sprint of its own, still under finish-or-revert.

1. **Discovery.** Clone SFBAudioEngine (MIT; pinned to the version the council read, 0.14.0 at 9ed712d), read it as data outside the repo's build, and analyse it at code level against our Enhanced path: the decode-ahead ring, gapless and format-change joins, seek, device and configuration changes, threading, events, sample-rate conversion. Write down where **our** implementation can improve, each tied to a council row. Design the new module's interface.
2. **Build our own engine** as its own SwiftPM module behind a clean interface. Enhanced first: a pull model (`AVAudioSourceNode` over Pure's proven C++ decode and gapless pipeline), the explicit Mastering converter from R1.1, our two audio units unchanged. Designed so Pure's decode can share it later. During the sprint it lands behind a developer switch with today's path as the default; the switch does not outlive the sprint (below).

## Agent control surface (MCP) *(founder, 2026-10-13; placed 2026-10-14)*

**Expose ALL of the player's functionality through a local [MCP](https://modelcontextprotocol.io) server**, so an
LLM client (Claude Desktop / Claude Code, the open-source agent [OpenClaw](https://bigdataboutique.com/what-is-openclaw),
or any MCP client) can drive AdaptiveSound: transport, queue, library search and browse, playlists, EQ and sound
settings, output devices and Pure Mode, and read the player's state.

- **One command layer, two front ends.** MCP tools call the SAME command / state API as the UI, never a second
  path. That makes it depend on the 2026-10 council's transport command / reducer and engine-event work.
- **Local and consented.** Off by default; enabled in Settings; local only (stdio or localhost); per-client scopes
  (read-only / control / library-modify); destructive operations confirmed; hearing-safety clamps enforced
  server-side for every client.
- **Placement (FD-8, 2026-10-14; amended 2026-10-23): after W2 — one owner for playback — and the command layer, in R2 or later.** No early
  spike: today's transport breaks under single-client interleavings, and an agent is a fast client. W2's engine half is
  the Engine sprint's and its transport half — the reducer and the command layer — is S15's slice; EP-MCP is a
  consumer of that command layer, not what funds it ([How structural work is paid for](#how-structural-work-is-paid-for)).
  ~~Placement: decided by the 2026-10 council, after the command-layer refactor wave.~~ Backlog: [EP-MCP](backlog.md#ep-mcp--agent-control-surface-mcp).
- **Relationship to the 2026-07-12 cut:** in-app conversational tuning stays cut. This is an *external* control
  surface. An LLM adjusting the EQ through MCP is a consequence the founder confirms explicitly (council decision list).
