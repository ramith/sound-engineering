# Roadmap review — where the sound features overlap, contradict or complicate each other

2026-10-23. Four independent reviewers (signal chain, other players' code and manuals, structure, listener), each reading the docs AND the source, none seeing the others. Their reports sit beside this file: `panel/dsp-chain.md`, `panel/other-players.md`, `panel/architecture.md`, `panel/listener.md` (every web source they opened is listed at the end of each). This is the merged, ranked synthesis for the founder. Numbers in brackets = which reviewers found it (L = listener, D = chain, A = architect, P = players).

Scope: the scheduled plan only — R1.1-B → Engine sprint → R2 (S14-lite, S12, S13, S11-lite) → R3 (S15–S18) — on top of what shipped. Deferred / won't / cut items were not reviewed.

## The one code fact under most of it
The only leveller in the kernel is a session-long automatic gain control (−16 LUFS target, makeup −20…+12 dB). It is `enabled = 1` by default, no code in the app writes it, and it runs only on the kernel paths Intensity selects — so "leveling off" today is a side-effect of Intensity being hidden at 0, not a setting (`Sources/AudioDSP/include/TargetState.h:64`; `DSPKernel.cpp:263-270, 313-319, 348-351`; `AudioViewModel.swift:188, 201`). Verified by all four reviewers and by me.

## Ranked findings

### 1. Leveling (R1.1-B) collides with the old leveller, and Intensity (S17) brings the old one back  [L D A P — all four]
- R1.1-B adds Leveling Off / Album / Track as a static gain, but the story names no stage for it: at Intensity 0 the kernel runs P1 (EQ → crossfeed → limiter), which has no loudness stage at all. The old AGC is not retired. The day S17 shows Intensity again, any value above 0 re-enables the AGC on top of the listener's static leveling — two levellers, one drifting 1 dB/s, regardless of "Leveling: Off". FD-2's faithful default silently ends.
- The same fix (C-38) is scheduled twice: R1.1-B in the roadmap, W5/S12 in the architect's slice catalogue.
- Its "sample-accurate at the seam" acceptance rides a seam the current engine counts a buffer early (KI-GAP-02) and which the Engine sprint replaces.
- Against other players: Roon/JRiver/foobar/MPD all have Off / **Auto** (album when adjacent tracks share an album, else track) / Album / Track, a fixed gain for tracks of unknown loudness (Roon −5 dB), a declared target, and read ReplayGain/R128 tags. Ours has none of the four, and the live causal fallback would move the level *during* a song.
- Pure: the story is silent. Others either disable leveling in bit-perfect mode or move it to the hardware mixer (MPD). If it is built on our device-volume loan without telling the loan, the loan reads the leveling cut as the listener's own change and re-anchors.
- **Must decide before R1.1-B. Recommendation:** leveling = one static per-track/album gain published through the existing `TrackLoudnessGain` → `eq.outputGainDb` (one gain owner, already seam-following, Pure-exempt by construction), on every path; the AGC retired in the same change (its `enabled` flag driven by the Leveling setting, default off); strike "loudness-comp" from S17; add Auto, a fixed unknown-loudness fallback, a displayed target (−14 LUFS matches Roon/Spotify), tags read when present; Pure = "Leveling off (bit-perfect)" in the badge for now.

### 2. Intensity (S17) is one knob over stages the listener will already switch separately, and Clarity (S16) ships into a path nobody can hear  [L D A P — all four]
- S17 still says "map Intensity across loudness-comp + clarity (+ crossfeed)". Crossfeed was moved out of the blend by your 2026-10-14 decision and plays at full strength whatever Intensity is (`DSPKernel.cpp:321-324`). S14 gives compensation its own switch; R1.1-B gives leveling its own. So the row contradicts two earlier decisions, and a listener would have two hands on each knob. Two stories give two defaults (FD-2: 0; US-ADAPT-05: "100 % (default)"); FR-REIMAGINE-02's "0 = all stages bypassed" would silently override a Loudness switch the listener set.
- Clarity runs only inside the Intensity blend (`DSPKernel.cpp:431-436`), and Intensity stays hidden at 0 until S17 — so S16's "core differentiator" has no audible path the sprint it ships, and its A/B is level-biased by the +3 dB equal-power hump S17 fixes later.
- Nobody else macro-scales level stages (Roon: per-filter switches, leveling outside MUSE; Pro-Q's one macro scales shapes only).
- **Must decide before S16. Recommendation:** Intensity scales only the automatic, perceptual stages — Clarity depth and the spatial room/spread — never crossfeed, leveling, compensation, EQ or correction; fix the S17 row, FR-REIMAGINE-02 ("0 = nothing automatic") and US-ADAPT-05; give Clarity its own switch (the pattern crossfeed took) or merge S16 and S17 so it is audible when it ships.

### 3. Loudness compensation (S14-lite) has no level to read, wrong dependencies, and two definitions  [L D A P — all four]
- It needs "a level input". In code, Master Gain on Enhanced is the player node's volume, applied after the whole kernel (`AudioEngineBridge+MasterGain.swift:44-46`); the device's own volume is read only on Pure (`:150, 172-178`) — the path with no DSP. So the kernel has the DSP and no level; Pure has the level and no DSP. A listener who leaves Master Gain at 0 dB and uses the volume keys or the headphones' own volume (your setup) gets no compensation at any level. That is not "the loudness button"; it is a tone control that moves when one slider moves.
- "Depends on: ENG" — but all of its code is in the effects AU's Realizer, which the Engine sprint leaves unchanged. "Waits for W2 (engine events)" — but the device-volume mechanism already exists as a HAL listener; it is gated to Pure, not missing. Neither dependency is real.
- Two definitions: LD-17 / FR-TONAL-03 say "loudness-matched makeup" (a tilt that costs no headroom); the council's C-09 says "exempt from neutrality" (a boost that, on a −9 LUFS master at the −0.1 dBTP wired ceiling, puts the limiter into sustained gain reduction). Two caps: +12 dB (sprint plan, backlog) vs +6/+4 dB (requirements). The backlog itself flags the clash.
- Naming: "Leveling" and "Loudness" are, to a Spotify listener, the same thing; to a receiver owner "Loudness" is a bass boost. Decision 31 renamed the "Loudness" preset for exactly this reason.
- Others: JRiver keys Loudness to its internal volume plus a user reference-level calibration; CamillaDSP's loudness filter follows the fader and, when the volume control sits *after* the DSP (our case), switches to **attenuate-mid** (cut the mids as level drops, never boost the extremes — no headroom, cannot clip).
- **Must decide before S14-lite. Recommendation:** decouple from ENG and W2; level = Master Gain dB + the Enhanced device's volume through the existing listener, relative to a one-time "this is my normal loud setting" reference (no SPL model); attenuate-mid form; one cap; plain names in one "Level" card ("Even out track levels", "Keep bass and treble at low volume") with a one-line readout of the net gain now applied; Pure says "not in Pure".

### 4. Gain and headroom have no owner; the ±12 dB "trust clamp" is not a sum  [L D A P]
- Today three independent ±12 dB limits (EQ points, the −ΔL neutral gain, the AGC makeup) and realized bells up to ±33 dB; nothing sums them before a true-peak-only limiter. The architecture's cumulative +12 dB clamp is in a section headed "DESIGN — NOT YET SHIPPED" (S15–S16).
- The plan adds taste + compensation (+12) + correction + leveling + Clarity's per-band gain: +23 dB of request in one band is possible before any limiter — and after S13 it is the auto-loaded correction, not the listener, spending the budget. "Respect the clamp, with its own headroom or a cap" is two rules in one sentence.
- AutoEq files carry a *peak-based* `Preamp: −6.1 dB` and filters to ±20 dB; our −ΔL is *loudness-based* and typically smaller, and gains beyond ±12 would be silently clamped — the "picture lies" failure your own EQ research warned about.
- Others: Roon has one fixed Headroom stage first (−3 dB default) plus a clipping light; Equalizer APO sums preamps; Strawberry has an EQ preamp element.
- **Should decide before S14-lite (it also sets R1.1-B's leveling cap). Recommendation:** one headroom ledger in the Realizer — per-band sum over the EQ layers ≤ +12 dB with proportional scaling, one pre-gain applied once before the EQ, AutoEq's preamp dropped on import and replaced by the ledger, the limiter's gain reduction metered and shown. Make it S14-lite's structural slice (the first sprint that adds a second boost).

### 5. The 5.1/7.1 fold-down (R1.1-B): a second limiter by default, crossfeed silently off, and five owners of the channel layout  [D A P]
- "A safety ceiling after the spatial stage" = a second true-peak limiter in an AU that today has no control plane, no publish path and no limiter (`SpatialRendererAU.mm:249-252`; `SpatialRenderKernel.cpp` only copies). The fold sums C and Ls at 0.707 into each side (+7.7 dB worst case, +3 dB on centred vocals), so a ceiling after it does sustained gain reduction on most dense 5.1 masters — compression by default on exactly the files R1.1-B exists to fix, contrary to LD-17.
- Crossfeed is stereo-only and runs *before* the fold at width N, so a headphone listener with crossfeed on hears a folded 5.1 album without it, and the "XF" chip still shows.
- The channel layout is resolved from `AVAudioFile` and published to the effects AU only; R1.1-B needs it in the spatial AU; the Engine sprint's decoder carries a count only; S12 (a PEQ feature that needs none of it) is told "the Realizer also owns the channel layout"; S18 needs the azimuths in the AU that never receives them. One part, rebuilt in four sprints.
- Others: JRiver "Output Format must be processed first"; CamillaDSP folds with explicit gains; mpv normalises the downmix.
- **Must decide before R1.1-B. Recommendation:** fold *inside* the kernel before the one limiter (so crossfeed, the limiter and the EQ's gains all see the stereo signal that reaches the device), or at minimum a per-track static fold trim from a folded true-peak the analyser computes, so the ceiling rarely acts; one decoded `ChannelLayout` per item, published to both AUs through one call; move "C-45's rest" and C-47's minimal form from S12 into R1.1-B, the sprint whose feature needs them.

### 6. EQ layers: four curve sources, up to three filter engines, three per-device memories, and "Compare" with no single meaning  [L D A P]
- By S16: the 31 exact SVF bells, S12's `FilterSpec` sections, and S16's Levenberg–Marquardt-fitted cascade approximating what the bells already do exactly — three realisers, three glide rules, and the RT parameter block (and golden master) changing shape at S12 and again at S16. S14-lite's compensation layer is built in the contract S12 then replaces. Two different things are called "Realizer".
- Per-device memory: the EQ pin (per device UID, model fallback, with KI-EQ-01's unpin-overwrites-shared defect), S13's "profiles" (bands + spatial + dynamics + strength + device id), and a PEQ with no slot story — no rule for which wins. S13's row says identification was "delivered early" by the pins; it wasn't — pins are per-device taste memory, not headphone-model identification.
- Compare today = "without my EQ, at matched loudness" (EQ only). After S13 that removes the headphone correction too — the wrong comparison. After S14 it would remove the compensation tilt, which is not neutral by design. S12's row lists the A/B as both "already shipped" (roadmap) and "open" (sprint plan).
- S12 is overloaded past the 2-week cap: PEQ + AutoEq + shelves + glide + `EQProgram` + layout + stage concept.
- **Should decide before S12. Recommendation:** one `EQProgram` = ordered layers [correction | taste (graphic + PEQ) | compensation] → one design step → one coefficient set, one composed read-back so the graph still "draws what plays", a bypass per layer; Compare keeps exactly one meaning ("without *my* EQ"; correction and compensation stay) and a separate latching "Bypass all processing" delivers US-PROF-02; the existing per-output slot is the only per-device memory, extended with the PEQ and the correction choice (fix KI-EQ-01 in the same change); S16's Arbiter emits into that program rather than running a second engine; S12 carries only the EQ part of W5; rewrite the S13 row honestly (identification, a correction layer keyed by model, the profile model or its explicit cut).

### 7. "Faithful by default" is broken by two planned auto-ons  [L D A P]
- S13: "automatically apply a correction … right out of the box" / "auto-load by identified device". S18: "HRTF is default-on for any device classified as headphones". A new install with your XM4 connected would be corrected (and later binauralised) before you touch anything, and the hero chip names only Intensity and crossfeed, so nothing on screen says so. The docs give three different readings of whether correction even has a switch.
- If correction is written into the pinned taste slot, a second pair of the same model double-applies through the model fallback. Device-class gating is a heuristic (a DAC feeding headphones is "USB"); others use per-device memory plus a manual override.
- **Must decide before S13. Recommendation:** correction and spatial are opt-in per device and off on a fresh install; "auto-load" means *offer and remember* (US-DEVICE-04's own wording), never *apply*; the device class only chooses the default for a never-seen output; a hero chip for every stage that plays.

### 8. Headphones: three answers (crossfeed, the fold, BRIR), no switch story, BRIR with two homes  [L D A P]
- The kernel declares crossfeed and BRIR mutually exclusive with "no arbitration code yet" (`TargetState.h:100-105`). BRIR exists as an N→N stub *inside* the Intensity blend in the effects AU, while S18 says it "replaces the fold in the same slot" in the spatial AU (N→2, after the limiter, outside the blend) — only one can fold, and only one can be blended. The S4 design the sprint plan still links chooses Apple's environment node, which the backlog bans.
- **Should decide before S18 (the Pure wording for the fold belongs in R1.1-B). Recommendation:** one "Headphones: Off / Crossfeed / Spatial" control, exclusive by construction, remembered per output; BRIR renders at the device boundary for every source width (stereo = the externalisation case), Intensity drives its room amount as a parameter, not a wet/dry blend; retire the kernel stub; mark the S4 design superseded; the fold gets a chip ("5.1 → stereo") and the Pure reason says "…so Enhanced plays it, folded to stereo".

### 9. Every planned sound feature is Enhanced-only, and only the EQ says so  [L D A P]
- Leveling, compensation, correction, Clarity, spatial: none of their stories mentions Pure. Today the EQ strip and the Settings row are honest; the crossfeed switch stays live-but-silent on Pure. Master Gain on Pure gives the Mac's volume back at end of queue with no word.
- **Should decide, first instance in R1.1-B. Recommendation:** one shared "Not in Pure Mode" row state applied to every DSP control; the Pure badge lists what is being skipped; the give-back raises a toast.

### 10. Sequencing: W2 has no slot, and the Engine sprint's neighbours lean on it wrongly  [A D P]
- W2 (one playback owner) is "funded by" EP-MCP while EP-MCP "waits for" W2; its size ("L, time-boxed per event family") cannot fit the 2-week slice rule; S15–S18 need "W2 events" per the council's own table but the sprint rows list no such dependency; in code there is no event channel, only a 20 Hz poll.
- R1.1 work sits on the path ENG removes (the one-converter seam, seek-to-end, roles from `AVAudioFile`, leveling's seam) but ENG's acceptance names council rows, not these behaviours to re-prove. ENG moves the graph to the device rate, which makes C-49 live (the EQ plays flat below 44 kHz — a Bluetooth headset with the mic on) with no owner, and the EQ-only −0.1 dBTP ceiling leaves ~0.3 dB before an unmeasured output-side conversion nobody else runs above −1 dBTP.
- **Must decide before S14-lite / S15. Recommendation:** ENG delivers the engine half of W2 (it already says so); S15, the first consumer, carries the transport reducer + command layer; drop "S14's adaptive half" as a funder; remove S14-lite's "Depends on: ENG"; ENG's acceptance carries the R1.1 contract tests and C-49/C-48; keep −1 dBTP everywhere until ENG measures the conversion.

### 11. Nothing forces your own litmus test, and "Clarity" names two things  [L]
- No story makes "familiar music sounds more transparent on a blind, level-matched A/B" the last acceptance line of S14, S16 or S18. S16 is the item most likely to fail it (the adaptive-tone study found no published test where automatic EQ beats a finished master). The council said "Clarity only if it wins a blind test"; that reached no story. US-SPAT-01's ABX proves *difference*, not *preference*.
- The built-in EQ preset is called "Clarity"; so is the S16 feature. The "Loudness" preset was renamed for exactly this clash.
- **Should decide before S15. Recommendation:** one acceptance line on every processing sprint — a blind, level-matched A/B on your own headphones and soundbar (the adaptive-tone §6 Stage 1 ladder, ~23 trials); a stage that does not win ships off and hidden. Rename the preset's display name ("Detail"), stored id unchanged.

## Doc-vs-code and doc-vs-doc contradictions found on the way
- S17 row maps crossfeed into Intensity; code and the 2026-10-14 decision put it outside (`DSPKernel.cpp:321-324`).
- US-R1F-12 says crossfeed "can be enabled on any output"; code gates it to headphones (`AudioViewModel.swift:233-235`).
- US-ADAPT-05 default "100 %" vs FD-2 Intensity 0. US-SPAT-01 "default-on" vs FD-2.
- C-38 (static leveling gain) scheduled in R1.1-B (roadmap) and in W5/S12 (slice catalogue).
- A/B bypass "already shipped" (roadmap S12) vs "open" (sprint plan S12).
- S13 "auto-load mechanism delivered early" — the pins are taste memory, not identification.
- LD-17 "loudness-matched makeup" vs C-09 "exempt from neutrality"; +12 dB vs +6/+4 dB caps.
- `LoudnessParams.makeupGainLinear` exists with no writer; the S4 binaural design still says "S17" and chooses Apple nodes the backlog bans.

## Checked and fine (all four agree)
P0's bit-exact anchor survives the plan (every added stage is opt-in); the limiter is correctly last inside the effects AU with crossfeed before it; Master Gain is one law on both paths, turn-down only, never restored louder; Pure refuses a channel mismatch so the fold never touches Pure's output; "our two AUs unchanged" keeps the kernel work across the Engine sprint; the faithful default is real in code, not only in the docs; leveling-as-static-gain, −1 dBTP safety limiter, bs2b with its own gain law, AutoEq's file format, level-keyed loudness compensation with a reference and a cap — all match what mature players do.
