## 0. What the code says that the proposal does not (read first)

1. **Pure leveling cannot be checked on the XM4.** Pure declines Bluetooth by design (`Sources/AudioDSP/include/PureModeBridge.h:58`, reason 2 "LossyWirelessCodec"), so on the XM4 Enhanced plays. The founder check (`docs/sprints/sprint-plan.md:99`), item 7's acceptance (`docs/product/roadmap.md:92`) and the hardware note (`docs/product/backlog.md:337`) all say "Pure … on the XM4". The soundbar reads `.fixed` and is excluded. The founder's only Pure output with a settable volume is the Mac's built-in output (speakers or the jack), inferred. → §10 Q5.
2. **Album gain has no data source today.** The analyzer runs only the current and next track (`Sources/TrackLoudnessKit/TrackLoudnessAnalyzer.swift:25-29`), caches in memory only (`:30-31`, `:107`), and never runs in Pure (`:34`; `Sources/AdaptiveSound/AudioEngineBridge+TrackLoudness.swift:22-23`). No store column holds loudness (grep over `Sources/LibraryStore` finds none). Album and Auto need every track of an album analysed and kept, and Pure leveling needs analysis in Pure. No story covers persistence or album scheduling. The two documents also define album loudness differently: pooled blocks with BS.1770 gates on the concatenation (`docs/architecture/architecture.md:441`), or a power-average over the tracks (`docs/product/backlog.md:2015`). → §5 panel question P2, §10 Q2–Q3.
3. **The analysis pass needs the fold matrix in wave 1.** The folded true peak and folded loudness (item 1, item 7) can only be measured through the same matrix the spatial unit will play, and roles from labels are not modelled yet: `ChannelLayout` carries weights, azimuths and an LFE flag, but no role per slot (`Sources/AudioDSP/include/ChannelLayout.h:16-23`). → `FoldMatrix` and roles move into S1, owned by lane 1. Lane 2 applies them.
4. **The fold's peak arithmetic does not close as written.** (a) The trim `min(0, C_work − TP_fold)` (roadmap item 1) ignores the leveling gain g and the turn-down G, which are applied upstream in the effects unit (`eq.outputGainDb`). (b) The effects limiter runs at width N, and its gain is linked across all channels, LFE included (`Sources/AudioDSP/Limiting/LimiterModule.h:262, 281-282`). So g's cap must also hold against the N-channel peak, not only TP_fold. (c) The LFE choice is known only at the end of the pass, so the pass must measure folded TP and loudness for both choices. → P3–P5.
5. **The engine cannot tell Compare from EQ Off.** The session sends `plays = current.isOn && !isComparing` (`Sources/EQEditKit/EQSession.swift:63-64`) through `publishEQ(points:isOn:)` (`AudioViewModel.swift:473`; C-ABI `AUAudioUnit.mm:282`). Matching Compare to `g + T` needs a flag. → S3.
6. **`QueueRestorePoint` is the "Restore previous queue" undo point** (`Sources/PlaybackQueueKit/QueueRestorePoint.swift:1-10`), not crash restore. Today the queue's rows live in the store's "current" playlist (debounced 250 ms, `AudioViewModel+QueueMirror.swift:19-34`), and its cursor lives in UserDefaults, written only at quit (`AudioViewModel+QueueHydration.swift:102-119`). That is two stores and no crash cadence. → a new Kit type (§3) and S5.
7. **A loose file in the queue cannot persist today.** The mirror drops slots that have no `trackID` (`QueueMirror.swift:41-49`). Yet US-LIB-02 asks for its restore and for "no orphan row" (`backlog.md:1255-1268`). → S5: the restore record holds loose slots by path.
8. **"Use this drive" cannot reuse the S8.4 move-match.** Its signature includes `(dev, inode)` (`LibraryStore+MoveMatch.swift:22-24`), and both differ on another drive. Same-path rebinding already preserves ids through the url key (`Schema.swift:165, 193` UNIQUE(url)). A new mount path needs an id-preserving re-root by `relative_path` (`Schema.swift:167`). No migration is needed (`folders.volume_uuid` exists — `Schema+RootVolume.swift:21-23`), inferred.
9. **The search rule exists twice, and the two halves disagree.** The Swift tokens are letters ∪ decimal digits (`LibraryStore+Search.swift:44`), while the FTS index uses `'L* N* Co M*'` (`Schema+SearchTokens.swift:30`), so N* and Co differ. ZWJ (U+200D, category Cf) splits a Sinhala conjunct ("ශ්‍රී" → "ශ්" + "රී"). The facet filters use substring matching (`FacetTextFilter.swift:13-18`), while the Songs filter is membership-only and keeps its sort (`LibraryStore+Search.swift:72-74`). The store's sectioned `search()` has no genre or playlist section (`:23-37, 98`). → Q7, Q8.
10. **Size.** Items 2, 3, 5 and 8 add roughly 5 SP to the sound half (inferred). The sound half alone is about 3 weeks. → §8.

## 6. Counter-examples (listed before coding; each becomes a test)

**Auto rule.** (1) Shuffle A(X) → B(Y) → C(X): all three get the track gain. (2) Shuffle plays X1 then X2: both get the album gain, because the permutation names X1's next before X1 starts (needs lane 4). Without it, X1 gets the track gain and X2 the album gain. (3) The next row is removed or reordered mid-track: the playing gain stays (frozen), and the new next decides only its own. (4) Songs with no album title are never "the same album" (`AlbumGrouping.swift:63`). (5) A compilation album: one album gain over differently mastered tracks, by design. (6) Track mode on a live album with continuous seams: the album gain for the group (card 1). With silence between tracks, each track keeps its own gain. (7) Album mode, album not fully analysed at track 1 (Q3). (8) A loose file has no album, so it gets the track gain or −5 dB.
**Shuffle with history, Repeat off.** (1) 100 songs, one pass: each plays exactly once, then the queue ends. (2) Previous ×N returns the last N in reverse. Next after Previous resumes the pass, never re-rolls. (3) Previous at the first song of the pass: with Repeat off it restarts the song; with Repeat All it goes into the last pass's history (Q10). (4) Shuffle turned on mid-song: the pass starts at the current song and the rest is permuted. Turned off: continue in queue order from the current song. (5) Append during a pass: the new song goes to a random place in the unplayed rest. Remove a played song: history skips it. Remove the next one: re-arm (C-17, `PlaybackOrder.swift:51-60`). (6) Play Next under shuffle plays next and counts as played. (7) Repeat One + shuffle: the song repeats, the pass is unchanged. (8) Kill mid-pass: the same permutation, position and history. (9) Up Next keeps showing queue order (Q10). (10) Repeat All: the new pass never starts with the song that just ended.
**One search rule.** (1) "beyo" finds "Beyoncé" in every tab and in ⌘F. "eyon" no longer does (substring → word prefix; Q7). (2) "මා" finds "මාල" and not "මිල".
