## 1. Objectives, assumptions, non-goals

**Objective.** An **immersive** music experience on **modern capable Apple-Silicon Macs (M1 Pro / 16 GB floor and up; LD-18)**, on headphones & speakers, that lets the listener **actually hear what's being played** (clarity, detail, correct balance, externalized stage), and that **adapts dynamically** — automatically to content, level, and device.

**Assumptions:** ample CPU/RAM/network (LD-10); good-quality sources (LD-11); macOS / Apple-Silicon-first; own-player latency is free (we are the clock).
**Non-goals:** audio repair/restoration (LD-11); lyrics/recommendation; Windows/DAW-plugin formats.

---

## 2. Architecture at a glance

A constant **spine**: a non-real-time **control plane** decides *what the sound should be*; a real-time **data plane** renders it. They communicate via a lock-free parameter snapshot down and a lock-free meter/analysis snapshot up.

```mermaid
graph TB
  subgraph CP["CONTROL PLANE — non-real-time (Swift + off-RT C++)"]
    direction LR
    PRE["Pre-analysis / Pre-separation<br/>(look-ahead, offline, cached)"]
    CTRS["Typed contributors<br/>device · loudness ·<br/>content-adaptive · user"]
    ARB["Arbiter<br/>compose typed contributions in ERB/Bark<br/>+ masking model + governing-principle clamps<br/>→ per-stem TargetState"]
    REAL["The Arbiter's fitter (off-RT; design)<br/>per-band contributions INTO the one EQ program —<br/>no second filter engine; BRIR kernels, mix matrix"]
    PRE --> CTRS --> ARB --> REAL
  end
  subgraph DP["DATA PLANE — real-time C++ kernel (Audio Workgroups)"]
    direction LR
    STEMS["N stems (or mix)"] --> PSC["per-stem chain<br/>EQ · dynamics · spatial(BRIR)"] --> SUM["re-sum → binaural / stereo"] --> OUT["output"]
  end
  REAL == "atomic publish: finished coeffs/taps + mix matrix" ==> PSC
  DP -. "meters / FFT / loudness (lock-free snapshot)" .-> PRE
```

**RT rules (every kernel line):** no heap alloc, no locks, no Obj-C/Swift runtime, no I/O; pre-allocate; bounded deterministic work per buffer; cross-thread state via atomic snapshot + ramping; the **Realizer does all design/fitting off-RT** — the kernel only ramps & runs finished coefficients.

> **Status note (built vs. target).** The diagram above is the **target** control-plane/data-plane architecture (the stem object engine is its full-fat form). The **shipped** pipeline is narrower — see **§2.5 Shipped pipeline** for what actually runs today. In short: the per-stem chain + the **perceptual** Arbiter + the **masking-driven** Realizer + masking/BRIR are **design, not yet implemented**; what ships is a stereo/N-channel two-AU graph with the EQ/Clarity/BRIR/Crossfeed/Loudness/Limiter kernel present (EQ live — since Sprint EQ an accurate 31-band graphic EQ that plays what it draws, loudness-neutral; Clarity/BRIR no-op stubs; Crossfeed real + default-off; Loudness/Limiter real), a steerable equal-power intensity blend, and a **control-plane `Realizer`** (off-RT, coalesces EQ / intensity / crossfeed / track-loudness intents, designs the EQ, sole publisher) — plus a parallel bit-perfect HAL output path. The control-plane `Realizer` is **distinct from** the perceptual Arbiter + masking-driven Realizer of §4 / ADR-006, which remain design. *(2026-10-23: the two are now named apart — the shipped control-plane object keeps the name `Realizer`; the design-only perceptual one is **the Arbiter's fitter**, and it emits per-band contributions INTO the one EQ program the control-plane Realizer designs — there is no second filter engine. §4.)*

### Two output paths (mutually exclusive per playback start)

The engine (`AudioEngineBridge`, reached from the app only through the `AudioPlaybackEngine` protocol) drives **two** parallel output paths; the active one is chosen at each `startAudio(fileURL:pureMode:startAt:epoch:)` call:

1. **Enhanced path (default)** — `AVAudioEngine`-hosted graph (built at 48 kHz stereo, `AudioEngineBridge+Lifecycle.swift:50`, then reconfigured to the source width). Owns decode (`AVAudioFile`), device routing (it plays on the system default output), and the render thread. Rate-mismatched files run through an explicit streaming **`AVAudioConverter` at Apple's Mastering algorithm, maximum quality** (`StreamingResampler`, `AudioFormatKit`; driven by `AudioEngineBridge+EnhancedResampler.swift`) — flat to 20 kHz, images and aliases ≤ −148 dB, bit-exact at equal rates, gated by `make gate` (R1.1-A, council C-26; it was the Normal algorithm until then). Files at the graph rate are scheduled directly with no SRC (`scheduleSegment`, so a start or seek can begin mid-file). Every start, seek and re-establish lands through one path — `restartEnhanced` / `commitEnhanced` (`AudioEngineBridge+EnhancedRestart.swift`): the request is placed by `SeekTarget` (finite, ≥ 0, the nearest frame, at or past the end = the track ends now), the file is prepared, and only then is the schedule replaced and the position base moved (council C-25). The graph itself runs at 48 kHz on every edge, so AVAudioEngine converts nowhere inside it; a device not at 48 kHz still gets AUHAL's own output-side conversion (unmeasured; the Engine sprint runs the graph at the device rate).
2. **Pure Mode path (bit-perfect, opt-in)** — a HAL-direct output engine (`HALOutputEngine.mm`, `kAudioUnitSubType_HALOutput`) that **bypasses `AVAudioEngine` entirely** and the DSP graph, playing on the app's device directly: hog mode + an integer physical format where the device allows (full bit-perfect), else a rate-matched float stream (`evaluatePureViable`, `AudioEngineBridge+PureMode.swift:25`). Decode is runtime-pluggable: **Apple-first, FFmpeg an opt-in fallback** (`FileDecodeSource.cpp`: Apple `ExtAudioFile` is the default and reference decoder). *(R1.1-A, FD-3, council C-99:)* FFmpeg is **off by default** ("Use FFmpeg for other formats", Settings ▸ Formats; `ListeningSettings.useFFmpeg` sets the one process-wide switch, `FFmpegLoader.h` / `FFmpegOptIn`); while it is off nothing `dlopen`s it. When on, it is used only for a file Apple can't open, loaded only from `/opt/homebrew/lib` or `/usr/local/lib` by its exact major-versioned name, only when the resolved file and its folder are owned by root or the user and writable by no one else (`vetLibrary`), opened by that path and checked with `dladdr`; the baked major-version guard stays. Enhanced decodes through `AVAudioFile` only, so a file only FFmpeg reads plays only in Pure. The residual risk — a third-party C parser in-process — is KI-SEC-01. *(R1.1-A, C-34 / C-33:)* why Pure isn't playing bit-perfect is one named reason (`PureModeReason`: the C++ policy's codes across the C boundary, `PureModeBridge.h`, plus the engine's own "waits for Master Gain"), shown beside the Now Playing badge and in Settings; Pure's pre-check reads the file through Pure's own decoder (`pureModeEvaluateFile` → `FileDecodeSource::probe`), and `bitExactness` labels a source deeper than what reaches the device "not bit-perfect" (Pure decodes through float32: 24 significant bits); where the device's integer word is narrower (`ditherWhenConverting`), the render's float → integer step adds TPDF dither (`TpdfDither`: xorshift64*, ±1 LSB triangular, rounded to nearest — no allocation or lock on the IO thread), and at the exact depth it stays the bit-exact plain conversion (founder 2026-10-16). A Pure seek parks the render callback on a `RenderGate` (`include/RenderGate.h`) instead of stopping the output unit (Sprint G, PR #86); since R1 (PR #88) `close()` bars new passes at once and waits only for the one inside, and a teardown never reopens the gate — a pass that outlives its unit's stop leaves its engine and source parked, never freed. User-toggled in Settings (`AudioViewModel.pureModeEnabled`, `AudioViewModel.swift:106`); falls back to Enhanced when the device/file combination isn't viable — since R1 (PR #88) that includes a file whose channel count is not the device stream's (`PureModePolicy.cpp:126-135`; mapping inside Pure is not done) and a device format the converter cannot write byte for byte (`NativePcmFormat::fromAsbd`, `include/PureModeFormat.h`); non-finite samples convert to silence (`FiniteSamples.h`). Pure has no EQ or effects (so EQ Compare is disabled there).

### The two-AU N-channel graph (Enhanced path)

```
player → effectsAU (N→N) → spatialAU ('aspz', N→M) → mainMixer → output
```
(`AudioEngineBridge+Graph.swift:64-73`; the reconfigure re-wires the same chain, `AudioEngineBridge+Reconfigure.swift:136-139`.)

- **effectsAU** (`AUAudioUnit.mm`; held as ONE `EffectsUnit` value — node + `AUAudioUnit` — in `storedEffectsUnit`, reached only through `effectsNode` / `withEffectsAU`, `AudioEngineBridge.swift:54-59`) hosts the C++ `DSPKernel` (`DSPKernel.cpp`). Chain: **EQ** (always, ahead of everything) → *coloration* Clarity → BRIR → **Loudness** → **Crossfeed** → **Limiter**. Clarity/BRIR are no-op stubs; Crossfeed is a real user-toggled stage, bs2b (default-off → bit-exact); Loudness/Limiter are real. Intensity is a **continuous equal-power wet/dry blend** of the coloration chain only — see "The kernel's four paths" below. ~~Default 0.20 (`AudioViewModel.swift:142`).~~ *(R1.1-A, founder decision FD-2, 2026-10-14: the default is **0** — P0 / P1, so no leveller, no blend and, with the EQ off, no limiter — and the control is hidden, Intensity held at 0, until S17 (`AudioViewModel.offersIntensity`). Since Crossfeed sat inside the blend, it was silent at 0 (KI-SND-05).)* *(R1.1-A, founder decision 2026-10-14: Crossfeed is an **output stage of its own** — after the blend and the normaliser, before the limiter (`DSPKernel::renderOutput`) — at its preset's full strength whatever Intensity is; it is bs2b, faithfully (council C-42), and plays on headphones as the one output classifier finds them (`classifyOutputDevice`: the data source first — the Mac's jack included — then the transport). The limiter's release is program-dependent (C-39).)*
- **spatialAU** (`SpatialRendererAU.mm` + `Spatial/SpatialRenderKernel.cpp`, subtype `'aspz'`, the bridge's `spatialAudioUnit`) is the **device-boundary render stage** that maps processing width N to device width M = min(N, device channels) (`AudioFormatKit/MultichannelFormat.swift:90-94`). When **M == N** it is a **bit-exact identity route**. When **M < N** (a 5.1/7.1 file on a stereo output — reachable on any stereo device) it runs the interim **channel-truncation stub** (`SpatialRenderKernel.cpp:61-81`, "TODO(S4)"): the first M channels play and the rest — centre, LFE, surrounds — are dropped. ### The kernel's four paths (`DSPKernel::process`, `DSPKernel.cpp:145-301`; Sprint EQ, PR #73)

Every block: non-finite samples are scrubbed to silence on every path (`:157-166`); the causal loudness tap sees the source (`:170`); the EQ adopts its target (`:174`). Then:

| Path | When | What runs |
|---|---|---|
| **P0 — bit-perfect** | Intensity settled at 0, the EQ an identity (flat or off) and crossfeed off, held for 2 s (`:191-212`) | Nothing: the in-place block is returned untouched (the limiter's look-ahead ring is kept primed). Entry and exit cross-fade over 5 ms with a correlation-aware constant-power law (`crossfadeWithBypass`, `:350-397`). |
| **P1 — EQ only** | Intensity settled at 0, EQ or crossfeed on (`:233-244`) | EQ → Crossfeed → Limiter at the **EQ-only ceiling** (−0.1 dBTP on a wired output, so a loud master's EQ On isn't squashed under its bit-perfect Off — decision 29, `Limiting/OutputCeiling.h`). No coloration, no normaliser. *(Ceiling scope amended 2026-10-23: −0.1 dBTP only where the link is lossless AND the output runs at the engine's rate — §0.)* |
| **P2 — full chain** | Intensity settled at 1 (`:245-252`) | EQ → Clarity → BRIR → Loudness → Crossfeed → Limiter, in place. |
| **Blend** | Anything between (`runBlendPath`, `:256-301`) | Dry = the **EQ'd** signal (decision 25: the blend never undoes the EQ); wet = the coloration chain; equal-power `cos/sin(r·π/2)` per sample; then Loudness with its contribution gliding toward `min(1, r/0.1)` no faster than 0↔1 per 2 s (decision 33), then Crossfeed and the Limiter. |

**Leveling and the turn-down ride the existing per-track gain.** `TrackLoudnessGain` (`Loudness/TrackLoudnessGain.h`) already publishes one broadband gain per track into `eq.outputGainDb` on the Realizer's queue, follows the audible-track change (`setCurrentTrack`, 10 ms τ) and the gapless-group rule (`TrackLoudnessGain.cpp:247-270`), and is Pure-exempt by construction (Pure has no kernel). The decided model adds g_level and T to the same gain — **one gain owner, every processed path, P1 included** — so a leveled track with the EQ Off leaves P0 (correct: it is not bit-exact) and plays the gain alone through the identity cascade (`EQModule`'s identity test requires 0 dB — `EQ/EQModule.h:25-28`; `TrackLoudnessGain::ownGainDb` returns 0 for an Off or flat EQ, `TrackLoudnessGain.cpp:104-121`, so g_level and T must be added **outside** that early return). The gain is applied after the cascade (`EQParams::outputGainDb`, `include/TargetState.h:32-33`) in the EQ module's own one-pole; the ledger's "one pre-gain before the EQ" (§9) is its *accounting* position — in a double-precision SVF cascade (`EQModule.h:5-6`) with a float32 bus a broadband gain before or after the cascade is the same signal to within float rounding, so the kernel's home for it stays `eq.outputGainDb` unless the Engine sprint moves it.

**The session AGC is REMOVED, not gated** (card 1). Today the only leveller in the kernel is `LoudnessModule`'s makeup: target = clamp(lufsTarget − integrated, −20, +12) dB, slewed 0.1 dB per gated block ≈ 1 dB/s (`Loudness/LoudnessModule.cpp:276-299`; clamps `LoudnessModule.h:55-57`; `kDefaultLufsTarget = −16`, `include/AudioConstants.h:34`), `enabled = 1` by default (`include/TargetState.h:60-66`) with **no writer anywhere in the app** (a grep over `Sources/` finds only the declaration), run only on the P2 and blend paths and faded by Intensity (`DSPKernel.cpp:37-43, 294-299, 348-351`). It is silent today only because Intensity is held at 0 (`AudioViewModel.swift:188, 201`), and would wake under any Leveling setting the day Intensity returns. R1.1-B deletes `LoudnessParams`, the makeup law and `loudnessContributionAt`'s glide, and the P2 / blend paths lose their Loudness stage; the readout meter (the Swift tap on `mainMixerNode`) and `CausalLoudnessTap` (the per-track fallback) are untouched. Removing `LoudnessParams` changes `sizeof(TargetState)`: re-measure `kMeasuredTargetStateBytes` and re-confirm the golden master (`TargetState.h:152-164`); the P1 golden master (`0xF0E1D4EF83763709`) should hold bit for bit — it never ran the normaliser — and the tests that exercise P2 / the blend re-baseline. **The proof it is gone, not hidden:** in the C++ harness, an Intensity sweep 0 → 1 → 0 with Leveling Off leaves the integrated LUFS of the output within **0.1 dB** of the input over the whole sweep (today the blend's hump and the AGC's makeup both move it), and no leveling-related field of `TargetState` changes across the sweep.

**After the removal the kernel has two paths, not four.** P0 (bit-exact) and the processed path; with the AGC gone and (S17) the equal-power blend gone, "P2" and "blend" have nothing left to select — Intensity becomes a scalar the Realizer folds into the Clarity and room parameters (§5). Until S17 Intensity is held at 0, so the P2 / blend code is unreachable; ENG may delete it, S17 must.

**The bit-exact anchor after the change (NFR-QUAL-03).** P0 requires `eq.outputGainDb == 0`, so Leveling On or a non-zero turn-down leaves P0 — correctly, the output is not the file. The fresh-launch MD5 null holds exactly in the faithful state: Leveling Off, the EQ Off, Headphones Off, Enhance off, Intensity 0 — which is what a new install is ("What persists", below).   - *The kernel's analysis workers* (`LoudnessModule`'s meter, `CausalLoudnessTap`) nap while audio flows and park when none reaches them — paused, leveling off, bit-perfect, no estimate (`include/WorkerParking.h`: a `std::atomic` wait; the render thread's push costs one atomic add, and a futex wake only when the worker is parked).
  - *VoiceOver*: a reading that moves while shown — the scrubber, the loudness meters, the scan strip — is one element with a fixed label, its reading in the value (quantised: the playhead to the second via `AudioViewModel.elapsedSeconds`, LUFS to the LU, the true peak up to the dB) and `.updatesFrequently` (`liveReadout(_:value:)`, `UI/Controls/LiveReadout.swift`).

### Gapless / continuous playback + auto-advance

- **Enhanced gapless** (`AudioEngineBridge+Gapless.swift` / `+GaplessRoll.swift`): resampler→resampler / passthrough→passthrough / cross-rate seams without `player.stop()`; AAC priming / MP3 LAME delay trimming is handled automatically by `AVAudioFile`/`ExtAudioFile` edit lists (`AudioEngineBridge+Gapless.swift:40-43`).
  - **One stream across a same-format resampled seam** (R1.1-A, council C-22; KI-GAP-04): when the next track has the playing one's format (rate, channel count, layout — `StreamingResampler.canContinue(with:)`), its frames continue the stream through the SAME Mastering converter (`continueStreamIntoNextTrack`), so the join converts exactly as one input would — measured bit-identical to one continuous conversion (`EnhancedSeamTests`), where a converter per track clicked at −13 to −27 dB re peak (±240 frames) and could land the next track a frame early. The reader takes the next track at the read after the playing one's last, with its last full and partial chunks still queued (186–372 ms at 44.1 kHz), so the end-of-file roll that raced the last buffers (P3 D39 b) is gone for these seams. The join is placed in frames (`outputFrame(atInputFrame:)`: the converter lines its output up with the input's timeline, ⌈n × out/in⌉); its chunk is scheduled as two buffers, and the completion of the ending track's last one counts the seam (`commitJoin`) — the count, `lastFileURL`, the loudness gain (`trackBecameAudible`) — when the player has consumed that frame, not when the decode ended (D40), and the playhead base moves back by exactly the ending track's length. A seek or re-establish before the join is heard starts a fresh converter and puts the taken track back on deck (`supersedeEnhancedScheduleLocked`); a stop or a new start drops it. A seam that changes rate or channel count, or a next track armed after the take, keeps the end-of-file roll with a fresh converter and its timing (KI-GAP-02). The end of a stream is its last buffer's, once heard — `.dataPlayedBack`, as on the passthrough sub-path (`playedBackCallbackType`; `.dataRendered` in offline manual rendering, which never reports it) — so the view model's stop at the end of the queue cuts nothing (R1.1-A, S-1; KI-GAP-06); the read iterations after the flush only roll in a next track already armed. The Engine sprint replaces this engine (one decode-and-convert worker feeding a ring, counted on the render side).
- **Pure gapless** (`GaplessSource.cpp`): same-rate sample-accurate seams. The file opens off every bridge queue (`pureModeOpenDecodeSource`), then arms on `engineQueue` (`pureModeEngineArmOpenedNextTrack`), `PureModeBridge.h:150-184`; a rate/format mismatch advances with a brief reconfigure gap. AAC/MP3 decode through Apple here too, so their encoder delay is trimmed; the FFmpeg fallback's trim is the open item ([US-PLAY-07](../product/backlog.md), S11).
- **What plays next** (council D41): the view model's ONE producer (`armOnDeck`) numbers every on-deck request (`OnDeckTicket`: the epoch of the start it follows, a sequence that is never reset), and the engine applies only the newest request of its current playback (`OnDeckGate`, threading rule 3). An admitted request takes effect at once: Enhanced sets the slot; Pure takes the old pick off immediately (`pureModeEngineClearNextTrack`, an exactly-once exchange with the render's seam claim) and arms the new one only after its file opens and only if its request is still the newest. Arming never replaces, and the end is final: a track that ended with nothing armed never seams into a pick armed later. So a last-moment change that reached the engine before the current track ended — its pick still opening, unable to join gaplessly, or unreadable — gives a short gap and the right song. After a queue edit (an append, a drag, a removal) the next song follows the edit (council C-17, `keepOnDeck` → `PlaybackOrder.onDeck(afterEditing:)`): in order it is the row now under the playing one, as VLC and foobar2000 compute it; a shuffle pick or a Play Next stands. Two residual windows remain, because a seam reports a count, not which track it played (follow-up F1, seam identity, closes both): **A2** — a request not yet admitted when the track ends (the rest of the main-thread turn, one hop, and any `engineQueue` backlog; on Enhanced then `resampleQueue`'s) finds the old pick still armed, so the old pick plays while the new one is shown — at a same-format resampled seam "ends" is when the stream takes the next track, 186–372 ms before the join is heard at 44.1 kHz (R1.1-A; the end-of-file roll took it 0–186 ms before), so this window is a chunk longer there; **A2′** — an edit made after a seam but before the view model's next tick (up to 50 ms, plus the 33 ms clock) is shown as playing while the pick the seam took plays. Known and deferred to the transport state-machine work: `ended` stays latched across a seek, so a scrub back into a track that already ended (with nothing armed) is lost — the next tick starts the next track.
- **Auto-advance**: the view model's 20 Hz tick (`AudioViewModel+TransportTick.swift`, running while a song plays or a transport command is on its way) reads the seam count and end flag from the engine's `snapshot()` copy (`TransportSnapshot`, `PlaybackQueueKit`; Sprint G — it used to poll `trackTransitionCount()` / `playbackEnded()` live) and arms the next on-deck track. Both paths satisfy one GaplessController contract (`AudioPlaybackEngine.swift`, "GaplessController contract"; `GaplessContractTests`).

### Device model (pin vs. follow)

- App-selected device is **authoritative** by default. A Settings toggle (`pinPlaybackToSelectedDevice`, default `true`) chooses behaviour when a **new** device connects mid-playback: **PIN** re-asserts the selected device; **FOLLOW** adopts the newly-connected default and re-establishes playback on it.
- Resilience *(superseded by Sprint G, 2026-10-13 — kept for history)*: an `AVAudioEngineConfigurationChange` observer re-establishes the Enhanced path after route/format changes; a `kAudioDevicePropertyDeviceIsAlive` listener **pauses** the Pure path on device loss (never auto-jumps).
- **One output-device path (Sprint G):** every output event — the device list, the system default output (`kAudioHardwarePropertyDefaultOutputDevice`), the app device's `DeviceIsAlive`, and `AVAudioEngineConfigurationChange` — goes through `AudioEngineBridge+OutputDeviceMonitor.swift` on `configChangeQueue`, which reads fresh facts and asks one tested rule, `OutputDevicePolicy.action` (`OutputDeviceKit`).
  - **Device lost while playing → pause, on Enhanced and Pure alike** (never continue on another device); the selection then moves to the new system default.
  - **The device the user chose is kept apart from the device the app plays on** (`OutputDeviceSelection`, R1 / council N92): only a pick in the device menu or turning PIN on moves the choice, held by UID so a reconnect under a new id still matches. The device the app starts (or re-initializes) on is not a choice: until the user picks, PIN behaves exactly as FOLLOW. After a loss the fallback is temporary — the app follows the system default and never re-asserts a device the user did not pick — and when the chosen device returns it is the app's device again, once the device menu would list it (an output stream: a Bluetooth device appears mid-handshake without one): the next Play plays on it, and playback that resumed on the fallback moves back (Enhanced restarts on it; Pure moves with the output). ~~In-session only: the choice is not persisted across launches yet.~~ *(R1.1-A, DEV-1:)* the choice outlives the session: the view model reads it back from the engine after a pick or PIN turned on (`chosenOutputUID()`), keeps it with the listener's settings, and hands it back at engine-ready (`restoreChosenOutput` → `OutputDeviceSelection.restoreChoice`). That is not a pick: the rule is asked with `.choiceRestored` and makes the chosen device the app's device when it is here — idle, so the system default is left alone until Play re-asserts it. The device the app launches on is still never a choice.
  - **System default changed outside the app:** PIN re-asserts the chosen device while Enhanced plays or is about to start (idle: left alone); FOLLOW adopts it fully — selection, per-output EQ, transport / limiter ceiling, rate readout, crossfeed check (`AudioViewModel.adoptOutput`).
  - **Device chosen while Pure plays:** playback restarts at the playhead on the new device; the normal start path picks Pure or falls back to Enhanced.
  - The app's own default changes settle without a loop (`selectDevice` sets the app device before the system default).
  - The output menu lists only user-selectable devices: hidden devices, private aggregates and the app's own `CADefaultDeviceAggregate-…` are excluded (`DeviceListPolicy`, C++; Sprint G).

### Threading rules (app ↔ engine)

*Sprint G, 2026-10 — the disconnect freeze. Evidence: [main-thread-audio-audit-2026-10.md](main-thread-audio-audit-2026-10.md).*

**Why.** Every AVFAudio accessor on a node of a live `AVAudioEngine` — `isPlaying`, `lastRenderTime`, `playerTime(forNodeTime:)`, `volume`, `outputFormat`, `installTap`, even `.auAudioUnit` of an attached unit, on *any* node — takes ONE engine-wide recursive mutex (`AVAudioNodeImplBase::GetAttachAndEngineLock`). `stop`, `start`, `pause` and `connect` hold it for their whole run, including the time they wait on the HAL; `player.stop()` also runs pending completion handlers synchronously inside it. When a device dies, macOS holds the device's lock for seconds, so a `player.stop()` waits in `GetDeviceLatency` and every other caller waits behind it. Switching headphones off froze the app for 3–7 s because the main thread's tick asked `isPlaying`. Shown by the audit's two offline experiments (a completion handler sleeping inside `stop()`; a slow `allocateRenderResources` inside `engine.start()`) and by forum thread [770787](https://developer.apple.com/forums/thread/770787). The same rule covers the CoreAudio HAL itself (`AudioObject*`, `AudioUnit*`, the Pure C-ABI).

**The rules.**

1. **The main thread never calls into AVFAudio engine objects, the HAL, an AU, or the Pure C-ABI, and never `.sync`s onto a bridge queue or takes a lock held across such work.** It reaches the engine only through `AudioPlaybackEngine` (`AudioPlaybackEngine.swift:59-241`), whose synchronous surface is copy-or-hand-off only: `snapshot()` (one `EngineSnapshot`: transport, signal path, loudness, EQ design rate — `EngineSnapshot.swift`), the publishes (EQ / intensity / crossfeed / output transport, which borrow the effects AU's pointer via `withEffectsAU`; Master Gain, queued onto `engineQueue` — on Pure it reaches the device from there, latest wins), `keepPureVolumeLoans` (queued onto `deviceVolumeQueue`), the spectrum and monitoring reads (wait-free triple buffers) and the monitoring switch (one atomic store), the pin and device id, and the chosen device (`chosenOutputUID()`, a leaf-lock read; `restoreChosenOutput`, a hand-off to `configChangeQueue`). The channel layout and the track-loudness profile are published by the bridge itself, never from the main thread. Everything that waits runs on a bridge queue.
2. **Queue ownership** (declared in `AudioEngineBridge.swift:231-298`).

   | Queue | Owns |
   |---|---|
   | `engineQueue` | Transport and graph: start / stop / seek, the graph build and reconfigure, initialize / teardown, every Pure C-ABI call (`withPureEngine` asserts it), on-deck admission (`OnDeckGate`: every `setNextTrack`, on both paths), the transport clock (a 30 Hz timer, running only while playing, that samples the playhead, seam count and end flag and publishes `TransportSnapshot`). |
   | `resampleQueue` | The streaming resampler and the gapless seam state; the buffer scheduling and completion chain. |
   | `configChangeQueue` | Every output-device event (device list, system default, `DeviceIsAlive`, `AVAudioEngineConfigurationChange`) and the re-establish. |
   | `deviceVolumeQueue` | The Pure device's own volume: Master Gain on Pure (`MasterGainOnPure` — the entry, the slider's moves, leaving, the loans a previous run left) and the device's change listener. |

   Waits run one way only, so no cycle can form: `engineQueue` may `.sync` onto `configChangeQueue` (listener bind / unbind), `resampleQueue` and `deviceVolumeQueue` (Pure's entry and leaving: the device lowered before Pure renders, put back after it stopped); `configChangeQueue` onto `resampleQueue`; `resampleQueue` and `deviceVolumeQueue` wait on no queue, and nothing `.sync`s onto `engineQueue`. CoreAudio listeners never run on the main queue.

   The table is the model, held by convention, not by a type. Where the code departs from it (council BR-1; the one transport owner, W2, is to close these — the comment on `AudioEngineBridge` lists the same three): the configuration-change re-establish drives the engine and player from `configChangeQueue` while `engineQueue` runs the transport (a play-intent re-check narrows the race, it does not close it); a failed gapless roll restarts through `playFile` on a global queue; and the two AU instantiate completions finish the graph build on whatever queue AVFAudio calls them on.
3. **Numbered transport requests.** The view model numbers each start / seek / stop (`nextTransportEpoch()`, `AudioViewModel+TransportCommands.swift`) in the turn the user asks for it — a Stop or Pause too, never later in its task — and the engine publishes a transitional snapshot stamped with that number at the top of the operation, before any slow work. The view model ignores older snapshots (`TransportSnapshot.isCurrent(for:)`), so the replaced track's end flag or playhead can never act on the new one (the SFB `sequenceNumber` pattern). **Newest stands** (council C-15): the engine runs a command only if it has not begun a newer one (`beginTransportOperation` returns `false` and changes nothing), so a Stop that a Play overtook on its hop to `engineQueue` no longer silences the song shown as playing; and the view model applies a command's outcome only while it is still the newest (`transportCommand`: a start, then its prime, or a stop; `finish(_:)`). A press while one runs acts on it — Space during a start pauses it, Next starts the next song, a second Play joins it — and the play / pause control shows what was last asked (`playIntent`). The tick auto-advances only with nothing on its way, and the on-deck is the view model's to re-arm only from a start's prime on (`onDeckIsLive`), so nothing is armed for a new playback before the prime takes its seam baseline. On-deck requests are numbered too (council D41): each `setNextTrack` carries an `OnDeckTicket` — the epoch of the start it follows (its playback) and a sequence that is never reset — and `engineQueue` admits only the newest request of the current playback (`OnDeckGate`; a start or stop begins a playback, a seek does not, and playbacks only move forward — a start or stop that reaches the queue after a newer one changes nothing, as the transport epoch only grows — since C-15 such a command is dropped before it begins a playback, so this is a second guard). Requests can reach the queue, and Pure opens can finish, in any order; the newest one still wins (SFB's sequence number + playback generation).
4. **`stateLock` is a leaf.** It is held only to copy or swap a field: no callouts, no HAL or AVFAudio work, no last release of an object under it (swap out, release after unlocking). The effects AU is ONE value (`EffectsUnit`: node + `AUAudioUnit`), borrowed with a count; the teardown waits for the borrows to end before releasing it, so a main-thread borrow can never become the last owner.
5. **Completion handlers only hop** (`resampleQueue.async`): `stop()` runs them inside the engine lock.
6. **Device loss pauses first.** The alive listener marks the path interrupted before any HAL read, so the main thread sees the pause at once even while the stop waits on the dying device.

**Enforced by:** semgrep (`.semgrep.yml:72-143`) `main-thread-no-audio-hardware` (all of `Sources/AdaptiveSound` except the bridge's own files — `AudioEngineBridge*.swift`, `PureModeSession.swift` — and the stall self-test: engine-bound `AVAudio*` types, the bridge's node accessors, HAL / AU / Pure calls, `.sync` onto a bridge queue), `main-thread-no-concrete-bridge` (outside the bridge the app holds only `any AudioPlaybackEngine`, so a downcast can't reach queue-confined members), `coreaudio-listener-not-on-main` and `bridge-not-main-actor`; and `make main-thread-stall` in the strict gate (`scripts/strict-gate.sh`; the self-test is `Debug/MainThreadStallSelfTest.swift`) — the real bridge and view model on an offline engine, holding the engine lock on purpose until the check releases it, and judged by behaviour, not a stopwatch: it passes only if main keeps finishing its work while the lock is held (probe rounds and main-queue round trips complete during the hold), and a main thread that waits on the lock fails it, named, at a generous hang cap (founder decision, test-rig redesign 2026-10). A regex can't follow calls, so a new synchronous member of `AudioPlaybackEngine` must be added to the self-test's `EntryProbe`.

The tonal/spatial/dynamic state is **not** a single dB curve. Each source contributes a **typed contribution**:

| Contributor | Emits |
|---|---|

**Arbiter** composes contributions **in the perceptual (ERB/Bark) domain** using a masking model — the affordable **excitation-pattern / masked-threshold (ERB) subset**, *not* full time-varying Moore-Glasberg partial loudness (which is ~50× too slow per channel and has no shippable implementation) — enforces **governing-principle clamps** (locked-band records written on user-confirm, cleared on undo/session-end), and emits a **per-stem `TargetState`** (EQ curve + dynamics + transient + spatial placement + level). The **re-sum is a managed mixbus** (§9), not a passive adder.

### Masking model selection (locked: Moore-Glasberg roex, ERB-rate)

**Model choice (ADR-006 amendment):** The Arbiter uses the **roex(p) auditory filter** excitation-pattern model on the ERB-rate scale (34 bands, 50 Hz–16 kHz), fitted from Moore, Glasberg & Baer (JASA 1997) psychophysical masking data. The level-dependent slope parameter `p = p₀ × 10^{-αL}` (where `L` is excitation level in dB, `p₀ ≈ 31.5`, `α ≈ 0.008`) captures the upward spread of masking's dependence on source loudness — critical for accuracy at high listening levels. Per-band masked threshold is the excitation pattern plus an absolute threshold floor (ISO 226 Table B.1). Implementation: vDSP vector multiply-accumulate for the 34-band roex convolution per frame; ~70 floating-point operations per frame (negligible off-RT cost).

**Why this model:** (1) Matches architecture coherence (ERB bands used throughout the DSP pipeline); (2) better physics than fixed-slope alternatives (level-dependent masking slope matches auditory measurements); (3) zero computational penalty (all candidate models run in microseconds); (4) directly parameterized on ERB → natural integration with the Realizer's biquad fitting. Research shows no perceptual difference in music enhancement quality between roex and simpler spreading functions (MPEG, Bark) in this application (off-RT, frame-averaged spectra, conservative unmask targets).

**Use:** Compute excitation pattern of the masking signal(s) per frame; evaluate masked threshold per ERB band; provide the masking depth (`masking_depth[n] = E[n] - T[n]`) to the clarity and between-stem-unmasking contributors. For between-stem unmasking (Phase 1.5), compute excitation of all stems except the target and evaluate against the target's level.

### Arbiter arbitration rules (locked)

**Hierarchical composition with proportional clamping:**

1. **Governing-principle lock (confirmed user intent):** When the user confirms an intent (e.g., "boost vocals"), the Arbiter records a locked band and direction in the `TargetState`. Auto-contributors (content-adaptive, masking, device-correction) cannot override the direction of a locked band; they may only refine *magnitude* within the band or propose moves in other bands.

2. **Additive composition (auto-contributors):** Contributions that model *different* physical phenomena (device frequency response + loudness compensation) are summed per ERB band. Contributions that model *the same* phenomenon with *different confidence* (e.g., two content-adaptive suggestions) select the more conservative (smaller change) or are blended by confidence weight.

3. **Proportional clamping:** If the sum of all contributions in a band exceeds the per-band hard clamp (e.g., +12 dB for low frequencies per LD-11), scale all contributions in that band proportionally rather than dropping one contributor entirely. This preserves the direction of user intent and auto-suggestions while respecting hearing-safety limits. *(2026-10-23: this rule ships before the Arbiter does — as the **headroom ledger** in S14-lite, on the composed EQ program's layers; the Arbiter later emits into the same program and inherits it. §9, §11.)*

4. **Governing principle floor:** On session load, all locked bands are replayed at the user's confirmed values. Undo clears lock-bands and reverts to mix level. Session end clears all locks.

**The Arbiter's fitter (off-RT; design — the shipped control-plane `Realizer` is a different object, §2.5)** turns each `TargetState` into finished, ready-to-run artifacts per the active **QualityProfile**: **minimum-phase** biquad cascades (default) or **linear/mixed-phase FIR** (opt-in / content-permitting, LD-13); BRIR convolution kernels; the stem-mix matrix. *Nothing is designed/fitted on the RT thread.* *(2026-10-23: for the EQ the fitter's job is to emit per-band contributions into the one EQ program — the control-plane `Realizer`'s `GraphicEQDesigner` then designs the one cascade; the fitter never owns a cascade of its own.)*

### Biquad cascade fitting (locked: greedy add + L-M optimizer, ERB-weighted)

> **Superseded as the realization path 2026-10-23 ([card 6](../product/roadmap-reconciliation-2026-10/README.md#card-6--eq-layers-compare-per-headphone-memory-s12--s13--s16)); retained as a record.** The Arbiter emits per-band contributions into the one EQ program; the shipped `GraphicEQDesigner` (31 SVF bells, WLS-solved so the cascade plays the drawn points) realises the composed program. Two minimum-phase cascades in series sum their ripple and the drawn curve stops matching the played one (the WLS solve assumes it alone plays the targets) — the reason for one engine (from DSP principle). The fitter below may still serve a non-EQ target (BRIR kernels, the stem matrix).

**Goal:** Convert the Arbiter's per-ERB-band target gain curve into a cascade of **1–10 biquad filters** that approximates it with ≤±1 dB weighted error, fit in ~10 ms off-RT.

**Algorithm (greedy iterative add):**

1. **Initialize:** Start with 2 biquads initialized at the frequency with maximum target gain (peaking type, Q=1.4, gain clamped to ±6 dB). Set the L-M optimizer loose to refine these 2.

2. **Optimize:** Run Levenberg-Marquardt optimizer on all current biquads jointly (semi-analytical Jacobian: log-magnitude separability in cascade, semi-analytical per-biquad derivatives). Terminate L-M when gradient norm < 1e-5, step norm < 1e-7, or 200 iterations.

3. **Evaluate error:** Compute weighted Chebyshev-adjacent error `E_max = max_k( W[k] × |H(f_k) − G_target[k]| )` over the 34 ERB band centers. This is the **maximum weighted absolute error in dB** (not RMS), which catches localized failures in perceptually salient bands.

4. **Stop or add:** If `E_max ≤ 1.0 dB`, accept the cascade. Else if cascade has < 10 biquads, find the band `k*` with largest weighted residual, initialize a new peaking biquad at `f_erb[k*]` with gain = `residual[k*]` clamped to ±6 dB, and loop back to step 2.

5. **Finalize:** Promote the lowest-frequency biquad to a **low shelf** and the highest-frequency biquad to a **high shelf** (for cleaner sub-bass and treble rolloff). Sort all biquads by ascending center frequency. Convert all coefficients from double to float; use **Transposed Direct Form II** (TDF-II) for numerical stability on the RT thread.

**Per-biquad parameter constraints:**

| Parameter | Bounds | Reason |
|---|---|---|
| Center frequency `f0` | 50 Hz – 20 kHz | Avoid poles near Nyquist; clip to audio bandwidth |
| Q | 0.5 – 10.0 | Hard ceiling at Q=10 for numerical safety (pole radius ~0.9993); Q > 10 is perceptually implausible for music EQ |
| Gain (peaking) | −12 dB – +12 dB | Safety clamp per LD-11; if optimizer wants to exceed this, add another biquad instead |

The L-M step applies box constraints by simple clamping after each update (projected gradient).

**Error weighting function (perceptual accuracy):**

Three multiplicative components:

```
W[k] = W_ath[k] × W_erb[k] × W_intent[k]  (normalized so max = 1.0)
```

- **W_ath[k]** (absolute threshold): Suppress error in bands near or below ISO 226 absolute threshold. At nominal 75 dB SPL listening level: `W_ath[k] = 1 − sigmoid((T_q(f_k) − 75) / 10)`, where `T_q(f_k)` is the 0-phon threshold from ISO 226. Primarily down-weights <100 Hz and >12 kHz.

- **W_erb[k]** (ERB normalization): Normalize by ERB bandwidth so higher-frequency bands (wider in Hz but narrower perceptually) don't dominate. `W_erb[k] = ERB_min / ERB(f_k)`, where `ERB(f) = 24.7 × (4.37f/1000 + 1)` (Moore & Glasberg).

- **W_intent[k]** (governing principle amplification): When the Arbiter marks a band as user-confirmed (governed by an explicit user target), weight it 4×. Arbiter annotates per-band `intent_salience ∈ [0, 1]`; set `W_intent[k] = 1.0 + 3.0 × intent_salience[k]`.

**Why weighted Chebyshev, not RMS?** Users A/B against familiar music at known levels. A single 3 dB error in the vocal band (2–5 kHz) is immediately audible even if the RMS error over all bands is 0.5 dB. Chebyshev error catches localized failures; the weighting ensures perceptually unimportant bands don't dominate.

**Convergence & timing:** Greedy initialization (starting at max-gain frequency) puts the optimizer in the right basin immediately. Typical convergence: 20–50 L-M iterations per greedy pass; 5 passes for a typical 8-dB curve = ~200 iterations total, ~5–15 ms on M1 Pro (double precision, vDSP vector math for biquad evaluation). Well within the ~1–2 second off-RT budget.

**Future optimization path (Phase 2):** Once you have a corpus of fitted cascades, train a small on-device **IIRNet** (Eghbalzadeh et al.) model to predict (target curve → biquad parameters) directly. Inference is sub-millisecond; trade L-M design flexibility for real-time responsiveness if you ever need live parameter sweeps.

Pre-separation pipeline: on add/first-play, run **Demucs 6-stem** offline (**MLX primary**, Core ML secondary — STFT/complex ops don't convert cleanly; runs on GPU, ~seconds/track, latency-free), **cache stems to SSD** (FLAC; bounded LRU, ~120–160 MB/track). Code is MIT; the **model weights are auto-downloaded on first run** — NC-trained, so *not* redistributed in the repo (keeps it MIT/Apache-clean and setup one-tap, per the founder's open-source + minimal-setup steer).

**Weights download & integrity (supply-chain security):** Weights are fetched from the **official Demucs GitHub releases** (primary) with a **fallback to Hugging Face MLX-Community** if GitHub is unreachable. **Integrity verification:** use GitHub's native release checksums (typically SHA-256, published in release notes or as separate artifact files); validate the downloaded weights against the pinned hash before loading. **Failure mode:** if verification fails or both sources are unreachable, warn the user ("Separation weights unavailable; operating in mix-only mode"), disable the stem engine (fall back to mix-level DSP only), and proceed with the rest of the app functioning normally. **Updates:** users obtain new model weights by downloading a new app version (in-app weight updates deferred to far-future roadmap). The weights download happens once (on first add/play of a track); subsequent plays load from the local cache (LRU).

**Security note:** the app enforces a **code invariant** that stems are only ever derived from user-supplied local files — never from tapped audio or DRM sources (LD-15). The separation pipeline source-type is type-checked; untrusted sources (tap/aggregate) are rejected at compile time. The kernel renders **N stem-objects** — each its own EQ + dynamics + **spatial placement** — but through a **shared late-reverb tail + a cheap per-stem early/direct filter**, *not* 6 independent full BRIRs (the ~6× cost cut; §7, §15). **Bass (≲120 Hz) is high-passed out of the spatial path and summed mono; the lead vocal stays centered** (review C4). Masking/unmasking is computed **between stems** (ERB subset, §4); **user moves can target a stem** (e.g. bringing up the guitar). Stems are **gated on a perceptual-artifact estimate (not SDR)** — guitar/piano are the least-robust 6-stem case; poor stems fold into "other" / fewer stems, and confidence **clamps the per-track Reimagine ceiling**. **Own-player-only**, and **stems are only ever derived from user-supplied local files — never tapped/DRM audio**; the live tap path (Phase 2) is mix-level; real-time-lite separation is a research track.

**The fold (R1.1-B interim → ENG final).**
- **The matrix.** ITU-R BS.775-4 Table 2, 5.1 → 2/0: **L′ = L + 0.7071·C + 0.7071·Ls; R′ = R + 0.7071·C + 0.7071·Rs** (−3.01 dB on the centre and the surrounds). 7.1 folds its side and back surrounds into their side at the same coefficient per the same table — only the 5.1 row was opened for the reconciliation; the implementer confirms the 7.1 row against the printed table. Coherent worst case 1 + 0.7071 + 0.7071 = 2.414 → **+7.66 dB** per side; a **centre-only vocal lands at −3.0 dB per side** (equal overall loudness — two channels at half power), a vocal at equal level in L, R *and* C sums to 1.7071 → **+4.6 dB** per side, a phantom-centre vocal (L = R, no C) is unchanged. Channel roles come from the file's labels (KI-MC-02, council C-44), never from positions.
- **The LFE — per track, from the analysis.** **Omit** (gain 0) when it is coherent with the mains' low band — a low-passed copy of the bass already in L / R / C (common film practice; including it would add that bass twice: +6.0 dB below ~120 Hz at full level, +4.6 dB at 0.707, +3.5 dB at 0.5 — boomy). **Include at 0 dB per side** (gain 1.0 into both L′ and R′) when it carries energy the mains do not — the conservative end, still under what the mixer heard (the LFE is stored 10 dB under its playback level by film convention — unverified this session; two-ear summation gives back ~3 dB, from DSP principle). **Default omit when unknown.** The trim below is computed *with* the LFE gain decided. Leveling is unaffected either way: BS.1770 weights the LFE 0 (`include/ChannelLayout.h:10-13`). A proposed decision rule, from DSP principle — the listen settles it, not the numbers: over the gated blocks in which the LFE's power exceeds −40 dBFS, take the normalised zero-lag cross-correlation ρ between the LFE and (L + R + C) low-passed at 120 Hz; ρ ≥ 0.7 over ≥ 80 % of those blocks = coherent → omit; else, if the LFE's power below 80 Hz exceeds the mains' by ≥ 6 dB in ≥ 50 % of those blocks = bass the mains do not carry → include; else omit. **Gate before it ships (founder):** on the XM4, one album whose LFE carries bass the mains do not and one where it is a copy, a bass-heavy passage three ways (omit / −6 dB / 0 dB) with the trim applied — pass / fail by ear.
- **The trim — per track.** trim = min(0, C_work − TP_fold) (§9's cap applied to the folded signal; C_work = the ceiling by scope minus the limiter's 0.27 dB working margin), TP_fold = the 8× true peak of the folded stereo with the LFE gain decided, measured by the analyser in the same pass as the folded loudness; the **−7.66 dB constant is the no-analysis fallback**. With Leveling On the trim is this exact rule (leveling fixes consistency, so the backstop never acts); a high percentile of the folded true peak standing in for the maximum (so one brief peak does not set the whole track's level) is **not in R1.1-B** — the histogram prototype (run the folded-TP analysis over the founder's surround albums: trims mostly within 0–3 dB → the per-track trim is clearly right; clustered near 7 dB → a constant is nearly as good) may reopen it later.
- **The folded loudness.** When N > M, leveling and −ΔL use the loudness of the **folded** stereo, not the six-channel figure: for uncorrelated channels the fold reads **1–2 LU under** the weighted 5.1 measurement (stereo power P_L + P_R + P_C + 0.5·(P_Ls + P_Rs) against the 5.1 sum P_L + P_R + P_C + 1.41·(P_Ls + P_Rs); from DSP principle) — borderline at the ~1 dB JND, and free in the same analysis pass.
- **Interim home (R1.1-B): the spatial unit, where the truncation stub lives.** A small control path into the spatial AU — today it derives N and M from the bus formats alone and has no publish path and no limiter (`AudioEngine/SpatialRendererAU.mm`; `SpatialRenderKernel.cpp`) — carrying one per-track `FoldParams` (the matrix gains, the LFE gain, the trim), ramped at the track change; and a **backstop true-peak limiter after the fold** (a second net, in series with the effects AU's: its own 3 ms look-ahead, the ceiling by scope, its gain reduction metered) that the trim keeps asleep — never a program limiter by default. **What the listener loses meanwhile, and must be told:** crossfeed does nothing on a folded file — it is stereo-only and sits upstream at width N (`Spatial/CrossfeedModule.cpp:18-22, 49-54`) — so the chip and the switch read the engine's own bypass (`CrossfeedModule::isBypassed`) and "XF" never shows when nothing plays (KI-SND-06); the badge reads **"5.1 → stereo"**; Pure's refusal reason reads "…so Enhanced plays it, folded to stereo". Nothing else: the second net is inaudible by design once the trim exists.
- **Final home (ENG): the fold inside the kernel, before the one net.** Crossfeed and the render after it, so a surround album gets the room exactly as a stereo one; **one decoded `ChannelLayout` per item, owned from the decoder onward and published once** (today it is resolved from `AVAudioFile` and published to the effects AU only — `AudioEngineBridge+ChannelLayout.swift:53-54`; the layout already carries the BS.1770 weights, the BS.775 azimuths and the LFE flag, `include/ChannelLayout.h:16-23`); the backstop and the spatial AU's fold go; S18's render takes the kernel's stereo-out slot. Nothing in the interim is thrown away: the matrix, the LFE rule, the trim and the analysis fields move house.
- **Measurements.** (1) The analyser's folded true peak against the measured 8× true peak of the actually folded stereo — an oracle, within 0.17 dB. (2) The backstop's (final: the one net's) gain reduction over the founder's surround albums with the trim ≈ 0 (< 0.1 dB). (3) A centre-only sine folds to **−3.0 dB per side**. (4) A stereo-in-5.1 file (C, LFE, Ls, Rs silent) folds to a **null** against the stereo file through the same chain — interim with crossfeed off; final: the folded crossfeed output equals the stereo crossfeed output, the null that proves crossfeed sits after the fold. (5) The "5.1 → stereo" badge shows exactly when M < N.

- **Headphones — BRIR-first.** Convolve with a **binaural room response** (HRTF + early reflections + late reverb carrying interaural difference); dry SADIE-II HRIR is the anechoic core *inside* the BRIR; headphone-correction EQ is for **timbre only** (it does not externalize). Synthesize the room (image-source + FDN) or use CC0/CC-BY IRs. **Head-tracking opt-in** (`CMHeadphoneMotionManager`, macOS 14+). Loader: `libmysofa` (BSD-3); convolution via vDSP / FFTConvolver (MIT).
  - **v0.3:** one **shared late-reverb tail across stems** + cheap per-stem early/direct filters (not one full BRIR per stem). **Room amount is content-adaptive** — less on already-reverberant material (avoid reverb-on-reverb wash that *reduces* clarity), more on dry sources. **Bass excluded from the BRIR path + summed mono; lead vocal kept centered** (depth/early-reflections allowed, not L/R spread) — binaural-izing bass or a centered vocal combs and destabilizes the phantom center.
- **Speakers.** **M/S width + ambience extraction with hard mono-compatibility** (preserve the M channel). Crosstalk-cancellation/transaural is an opt-in "centered near-field desk" mode (stereo-dipole narrow span) — never aggressive XTC blind on laptop speakers.

## 9. Dynamics & loudness (LD-17 · ADR-010)

- **Re-sum mixbus (review C3 · ADR-011):** the per-stem chains sum through a *managed bus*, not a passive adder — **per-stem makeup ≤ gain-reduction removed** (no net loudness from per-stem dynamics), a **loudness-matched per-stem trim** so the sum's loudness + spectral centroid track the intensity-0 reference, a **headroom budget** (~−6…−3 dBFS pre-limiter so the safety limiter rarely engages), and **metered limiter gain-reduction** so "transparent" is verifiable. Centered content (kick/snare/bass/lead vocal) is group-delay-aligned to limit comb filtering on re-sum.
- **Dynamics:** transparent **LUFS normalization** + a **true-peak safety limiter** (≥4× oversampling, −1 dBTP, ~1 ms look-ahead, ITU-R BS.1770-5). **No program DRC by default**; if any, prefer **dynamic EQ** over multiband compression. *(Shipped: the normaliser targets −16 LUFS (`AudioConstants.h:34`); the limiter uses an 8× polyphase true-peak detector (`TruePeakKernel.h:27`) and a **3 ms** look-ahead (`AudioConstants.h:30`), −1 dBTP — −0.1 dBTP on the EQ-only path to a wired output.)* *(Amended 2026-10-23: "transparent LUFS normalization" = ONE static gain per track or album at −18 LUFS, Off by default; the shipped session normaliser is removed; the −0.1 dBTP ceiling is scoped to lossless-and-engine-rate outputs — "Decided target" below.)*
- **Loudness compensation** *(not built — forward-plan S14)*: a **fraction** of the equal-loudness **contour difference** (ISO 226) between an assumed program reference and the actual playback level; requires a **per-device SPL calibration**; **loudness-matched makeup**; **rate-limited to volume changes** (never program dynamics). Defeatable. *(Amended 2026-10-23: no SPL calibration — a one-time "my normal loud setting" reference and a loudness-matched level reading; the curve bass-only (≤ 1 kHz), published in the ease-the-mids form; one cap, +6 dB — "Decided target" below.)*
- **Psychoacoustic bass:** multiband + transient/steady-state hybrid NLD, **mono-summed**, **device/SPL-gated** (only when the transducer can't reproduce the fundamental). ⚠ Patent: mono-sum avoids Waves US-11,102,577; IP review before release (OQ-16).

### Decided target (2026-10-23), not yet shipped — level has one owner

The engineering form: numbers, formulas, owners and the proving measurement. **Symbols:** L = a track's integrated loudness (BS.1770-5, gated, LUFS); TP = its true peak (dBTP, the shared 8× `TruePeakKernel`); C = the active nominal ceiling by scope (dBTP; §0); **C_work = C − 0.27 dB**, the limiter's *working* ceiling (`kIspSafetyMargin`, `Limiting/LimiterModule.h:103-105`: the detector's < 0.17 dB under-read + a 0.10 dB guard) — every cap below targets C_work, not C, so the net reads 0 dB of gain reduction rather than up to 0.27 dB on every peak (a refinement of the reconciliation's "ceiling − TP", from the code's own margin); ΔL = the loudness change the **taste** layer makes on this track (`predictLoudnessChangeDb`, `Loudness/TrackLoudnessProfile.h:123-135`); H(f) = the composed EQ program's played response in dB (the designer's read-back, `EQ/GraphicEQDesigner.h:76-87`); B_max = max_f H(f) ≥ 0, its largest boost.

**1. Leveling (R1.1-B) — one static gain per track or album; the session AGC removed.**
- **Modes:** **Off** (the default — a fresh launch plays the file) / **Auto** / **Album** / **Track**. Auto = the album gain when the neighbouring track — the one just played or the next — is from the same album (the library's album identity), else the track gain; a gapless album takes the album gain — the rule Roon, JRiver, foobar2000 and MPD share. A continuous gapless seam inside an album takes the **album** gain even in Track mode (the gapless-group rule of `Loudness/TrackLoudnessGain.cpp:247-270`, generalised: the group shares the album gain; never a step while the music sounds).
- **Target L_T = −18 LUFS**, shown on the Leveling row in Settings (R1.1-B; founder, 2026-10-25) and later in the Level card. Why −18, not −14 or today's −16 (`include/AudioConstants.h:34`): under the true-peak cap a track can only be raised until its peak meets C_work; dynamic masters (−18 … −22 LUFS with peaks near full scale) cannot reach −14 and sit 2–6 dB under it while loud masters sit on it — the leveling is *less* even at −14; at −18 almost everything is a cut and reaches the target (ReplayGain's and foobar2000's choice; EBU R128's −23 is the broadcast form). No tonal difference at any target — a constant multiply; the volume knob sits ~4 dB higher than at −14, free on headphones or a DAC with its own volume, 4 dB of 24-bit headroom on the Mac's digital volume (from DSP principle).
- **The gain:** g_track = L_T − L_track; g_album = L_T − L_album, with L_album the gated loudness of the album's blocks pooled (BS.1770's gates applied to the concatenation, not the mean of the tracks' loudnesses). **Capped by the true peak:** g ≤ C_work − TP (per album: the album's loudest TP), so the net never acts on a leveled track — exact only with the analyser's new TP field (§2.5 "Who owns each quantity"). With the EQ on the cap is the turn-down's (2).
- **Unknown loudness** (not yet analysed, no tag): a fixed **−5 dB** cut (Roon's rule). **File tags** are read only for a track not yet analysed, ahead of the −5 dB cut: ReplayGain `REPLAYGAIN_TRACK_GAIN` / `_ALBUM_GAIN` re-referenced from −18 LUFS, R128 `R128_TRACK_GAIN` / `_ALBUM_GAIN` (Q7.8 dB, re −23 LUFS) — g = tag + (L_T − the tag's reference); our own analysis replaces the tag when it lands (scanners disagree by 1–3 dB on the same file — from practice, unverified to the decibel). **Never a live causal guess that moves the level mid-song**: `CausalLoudnessTap` stays the −ΔL fallback only.
- **What may move, and an album not yet analysed (founder, 2026-10-25, as recommended).** The listener's own change of the Leveling mode mid-song applies at once with a short glide (the listener's act, like the volume knob); automatic changes — an analysis landing, a tag read, the next track's album — never move the level inside a song. **Album mode before an album is fully analysed:** the album tags if every track has them; otherwise the track plays at its own gain and the album gain starts at the next seam across silence — never a step at a continuous seam. Where the analysis lives: §2.5 "What persists".
- **Owner and application:** `TrackLoudnessGain` → `eq.outputGainDb`, **every processed path**, published at the audible-track change (`Realizer::setCurrentTrack`, τ = 10 ms, `kTrackChangeRampSeconds`) — "sample-accurate at the seam" reads as "at the seam as the engine counts it" (`trackBecameAudible`) until the Engine sprint counts seams on the render side. The control-plane `Realizer` gains a leveling intent (the mode, and the per-track / per-album gains the app computes from the analysis); its intent surface today is EQ / Intensity / crossfeed / track loudness / output transport only (`AudioEngine/Realizer.h:118-146`). The AGC's removal, with its proof test, is §2.5 "Decided target".
- **The seam contract for leveling (the one sentence other documents quote):** in Album mode — and in Auto when track B is from track A's album — **one album gain holds across the whole gapless group**, set before its first track starts and never changed at a seam inside it; in Track mode **B's own gain applies on B's first audible frame as the engine counts it** — the completion of A's last scheduled buffer (`trackBecameAudible` → `Realizer::setCurrentTrack(token, gaplessSeam: true)`), within one buffer of the true join until the Engine sprint counts seams on the render side — glided over 10 ms; except that a **continuous** gapless seam (music above −50 LUFS on both sides, judged from the analysed profiles, `TrackLoudnessGain.cpp:247-270`) takes the **album** gain for both sides, decided before A starts from A's analysed tail and B's album identity, so no gain ever steps while the music sounds.

**2. The peak-safe turn-down T (R1.1-B; the measured form as soon as the analysis can).**
- **The pre-gain protects the peak AFTER leveling.** Three quantities: the **loudness-neutral offset** −ΔL (the taste layer's only — the **compensation layer is exempt**: its level change is read by the loudness button, never neutralised); the **leveling gain** g (0 with Leveling Off); and the **pre-gain** (the cap — C_cap in the backlog's numbers) = C_work − (TP + g + B_max) in the bound form — the track's true peak plus the leveling gain plus the program's largest boost — or C_work − TP_H − g in the measured form, where TP_H is the true peak of the track **as EQ'd** at 0 dB broadband gain. **The published broadband offset is the smaller of the loudness-neutral offset and the pre-gain**; the total gain in `eq.outputGainDb` is **G = g + min(−ΔL, pre-gain) = min(−ΔL + g, C_work − TP_H)**, and the turn-down shown is **T = min(−ΔL, pre-gain) − (−ΔL) ≤ 0** ("−2.3 dB so the net never works"). On a quiet track the pre-gain is positive, the neutral offset wins and T = 0 — which is why the pre-gain is a cap, not a min(0, ·) on its own. The reconciliation's earlier one-number form, ceiling − TP − the curve's boost, is this with g and ΔL left out; every document now carries the three-number form.
- **TP_H, two forms.** *Bound (R1.1-B):* TP_H ≤ TP + B_max — one number from the analysis and the designer's read-back; it over-turns-down whenever the track's peak and the curve's boost do not coincide in frequency. *Measured (the "per-curve peak scan", as soon as the analysis can):* TP_H = the 8× true peak of the decoded track filtered by the composed program, computed off-RT (in the analyser, or a Realizer job over the decoded track) — it turns down less on most tracks and is the form to keep. Re-computed on every EQ edit as −ΔL is today (decimated during a drag; refreshed in full after 150 ms idle — `Realizer.mm`, A6).
- **Compare is level-matched to it.** While held, the identity cascade is published with **outputGainDb = G + ΔL** — the loudness the EQ-on program plays at, minus only the curve — so Compare answers "is my curve helping?" at equal loudness on hot masters too. Today Compare publishes 0 dB (`AudioEngine/Realizer.mm:397-410`; `TrackLoudnessGain.cpp:104-109`), level-fair only while G = −ΔL. Correction and compensation (S13, S14-lite) stay in on both sides. Tolerance **0.2 dB** (the predictor is within 0.14 dB on broadband music, `TrackLoudnessProfile.h:19-20, 28-40`).
- **Measurements:** a −9 LUFS master with a +12 dB bass point at the wired −0.1 dBTP ceiling — gain reduction < 0.1 dB, the output's true peak ≤ C within the detector's 0.17 dB, EQ-on vs Compare loudness within 0.2 dB. The fold's trim (§7) is this rule applied to the folded true peak.

**3. The headroom ledger (S14-lite — the first sprint that adds a second boosting layer).**
- **The per-band sum.** At every design point the program is solved on (the 31 centres and the 30 geometric midpoints, `EQ/GraphicEQDesigner.h:10-13`) the ledger sums the layers' target contributions — correction + taste + compensation (Clarity's dynamic gain joins in S16) — and holds the sum at **+12 dB** by **proportional scaling** of the positive contributions in that band (§4 rule 3; §11): every layer keeps its direction, and the graph shows the band as **"protected"** (never "refused"). The per-point ±12 dB input guard stays (`EQEditKit/EQBands.swift:26`; `Realizer.mm:209`, `kEQMaxGainDb`); the *solved* bell gains may still exceed ±12 (up to ~±33 dB on jagged commands, the cascade's interaction — `GraphicEQDesigner.h:43-45`) because they are not the played curve. Cuts are not summed (no hearing risk; the −15 dB artifact cap of §11 stays design).
- **One pre-gain, applied once.** The ledger publishes the **two numbers** that are conflated today — the loudness offset G_loud (exists, as −ΔL) and the peak-safe cap G_cap — and the one broadband gain G = min of the two, in `eq.outputGainDb` (§2.5: its accounting position is "before the EQ", its home the EQ module's output gain). **AutoEq's `Preamp:` line is dropped on import** (it is a peak bound, −compound.max_gain; ours is loudness-based and, with the scan, measured) and replaced by the ledger — a corrected headphone is neither 6 dB too quiet nor hitting the ceiling.
- **The net's work is metered and shown.** `LimiterModule` exposes its gain reduction (a wait-free scalar per block — the deepest reduction in dB — read by the UI timer as the meters are, §14; it has no such telemetry today); the Level card's readout shows it ("the net would have worked: 0.0 dB").
- **Measurements:** the stacked worst case — taste +12 dB at 60 Hz + compensation at full depth + an HD 650 correction — on a bass-heavy −9 LUFS master at the wired ceiling: ledger output ≤ +12 dB in every band, gain reduction < 0.1 dB, the whole program's LUFS change vs Off within the compensation's own designed amount; the drawn-vs-played log sweep through the chain matches the composed read-back within 0.1 dB.

**4. The loudness button (S14-lite) — "Keep bass at low volume".**
- **The level it follows.** **level_ear = Master Gain dB + the device's own volume dB where it reads + g + T + the compensation layer's own loudness change (its cut)** — everything that changes the level at the ear: the app slider (`masterGainDecibels`), the HAL volume (`kAudioDevicePropertyVolumeDecibels`, through the listener that exists today only inside Pure, `AudioEngineBridge+MasterGain.swift:140-156`, lifted out of that gate), leveling, the turn-down, and this layer's cut. The cut depends on the reading, so the Realizer solves the pair **off the audio thread as a fixed point** — "volume minus its own cut" (the cut is bounded, so it converges) — never per buffer; there is no loop. Against a **one-time reference per output**: "this is my normal loud setting" stores level_ref = the same sum at that moment (leveling at the chosen target, so changing the target later does not move the compensation). The turn-down **D = max(0, level_ref − level_ear)**. This replaces LD-17's / ADR-010's per-device SPL calibration — the app never needs absolute SPL. Which applies is decided per output at run time by whether the volume reads — never by device type (it reads on the XM4 today; the soundbar's reads `.fixed`). An output whose volume does not read (`.fixed`, `+MasterGain.swift:209-213` — the HDMI soundbar) gets a **manual, labelled "Loudness amount"** that sets D by hand (dB of assumed turn-down, 0–20 dB; the depth fraction stays the global setting; the same curve law). Decoupled from the Engine sprint and W2: the volume source is a HAL property listener, not an engine event. **One check owed:** whether the XM4's own buttons move the Mac's HAL volume (AVRCP absolute volume) — if not, no app can see them and the caption must say "use the Mac's keys" (§17).
- **The curve — bass only.** The ISO 226:2003 equal-loudness contour difference relative to 1 kHz, between the reference phon level φ_ref (default 80 phon) and φ_ref − D: **C(f, D) = D − [L_p(f, φ_ref) − L_p(f, φ_ref − D)]**, applied **only below 1 kHz** — nothing above 1 kHz. Computed from the ISO 226:2003 formula and coefficients (IoSR `iso226.m`; the printed standard was not opened — **confirm against the printed tables in the S14-lite spike**). For D = 20 dB (80 → 60 phon): **+10.5 dB at 20 Hz, +8.2 at 50 Hz, +6.2 at 100 Hz, +3.9 at 200 Hz, +1.2 at 500 Hz, ~0 from 1 to 8 kHz** (−0.6 dB at 2–4 kHz, +0.3 at 8 kHz, +1.4 at 10 kHz — all discarded by the ≤ 1 kHz rule); for D = 10 dB about half. The former "+3–5 dB at 8–12 kHz" treble lift would add brightness the ear does not ask for — fizz — and is deleted everywhere.
- **Depth and cap.** The lift is **k · C(f, D)** with **k = 0.50 to start**; the prototype evening on the XM4 — three familiar loud masters, a 20 dB turn-down, the curve pre-rendered at 40 / 50 / 60 % — settles k in **40–60 %**. **One cap: +6 dB** in the bass (it engages only at full fraction and deep bass: at k = 0.5, D = 20 dB the lift is +3.1 dB at 100 Hz, +4.1 at 50 Hz, +5.3 at 20 Hz). Why well under 100 % (from DSP principle): the contours are pure-tone, in-quiet data, and on broadband music the masking between neighbouring bands reduces how much the balance shifts with level (the Moore–Glasberg partial-loudness view); the mix engineer's monitoring level is a guess; a quieter listen is expected to sound a little leaner. Too much sounds thick and boomy, vocals pushed back, the tone chasing the volume knob; too little sounds like an ordinary thin late-night listen.
- **The form — ease the mids, never boost.** The three forms are one curve at three heights — boost k·C; loudness-matched k·C − ΔL(k·C); ease-the-mids k·C − max_f k·C — identical at equal final loudness; they differ only in headroom (from DSP principle). Published: **curve_comp(f) = k·C(f, D) − max_f k·C(f, D)**, so its maximum is 0 dB — it spends no headroom, counts as 0 in the ledger, and the net never wakes; the music is a notch quieter and the caption says "nudge the volume up a notch". The layer is **exempt from the neutral gain** (no −ΔL on it: it is a deliberate loudness change) and its own loudness change **is counted in level_ear** (the level definition above — read, not neutralised), while the ease-the-mids form costs no *headroom*. (Reading the fader alone would under-compensate by ≈ 1/(1 + f) once the listener restores loudness, f ≈ 0.3 dB of cut per dB of turn-down at k = 0.5; the fixed point solved off-RT gives the designed tilt at the perceived level, and because it is solved once per volume event, never per buffer, there is no loop.)
- **Where and when.** The compensation layer of the one EQ program (§2.5): the curve sampled at the 31 centres, composed with the taste points (and the correction layer once it exists), designed once; re-designed on a **volume event only** — a Master Gain publish, the HAL listener's change, a leveling or turn-down change — and glided through the program's own per-band τ (amendment 15); never from program dynamics (LD-17's rate limit). **Pure:** disabled, and the control says "Not in bit-perfect mode". **Enhance never turns it on before the reference is set** — an uncalibrated loudness button is a tone control at the wrong level.
- **The Level card.** One card, in signal order, plain names — "Even out track levels" (Off / Auto / Album / Track, the target shown) and "Keep bass at low volume" (on / off, the reference step, the depth, the manual amount where the volume is unreadable) — and a **net-gain readout**: g, T, the compensation's own level change and the net's work, as numbers; "Not in bit-perfect mode" on Pure. ~~Its home (Settings or the inspector) is a UI call.~~ *Amended 2026-10-25 (founder):* in Settings, where the Leveling row lives (R1.1-B), unless the founder decides otherwise at S14-lite.
- **Measurements:** (1) a 20 dB fader step changes the realised response by the designed tilt — a sweep through the chain read back against the composed curve within 0.1 dB; (2) gain reduction < 0.1 dB on a −9 LUFS master at full depth (the boost form would show the `Limiting/OutputCeiling.h:6-8` behaviour: > 1 dB of reduction up to 74 % of the time); (3) the loop check — after the listener restores loudness, the published tilt equals the designed one at the perceived level; (4) the blind ladder at the founder's real late-night level with the reference set, "with" vs "without" nudged to equal loudness (§16).

**5. The ceiling by scope.** §0, decision 29 as amended: −0.1 dBTP only where the link is lossless **and** the output runs at the engine's rate; −1 dBTP elsewhere. `Realizer::setOutputTransport` (`Realizer.h:146`) gains the output's nominal rate — or a "conversion after the engine" flag — beside its transport, and `eqOnlyCeilingLinear` (`Limiting/OutputCeiling.h:24-40`) gains the rate condition — today it keys on the transport alone, so a 44.1 kHz USB DAC would get −0.1 dBTP ahead of an unmeasured conversion: latent on the founder's gear until a non-48 kHz wired output, settled by the Engine sprint's conversion measurement, tracked as KI-SND-07. With T in place the net sleeps at either ceiling, so the ceiling stops deciding squash-vs-quiet: "quieter by the turn-down" is the honest price of a hot master, and a constant offset is far more transparent than sustained limiting (from DSP principle).

**6. "Bypass all processing".** A separate, latching control — not Compare: the kernel's P0 state (the identity program at 0 dB, leveling and the turn-down included; Headphones Off; Clarity off), so the output is the file, bit for bit, while latched; the chip says so. It is **not level-matched** — it plays the file as recorded, level and all. **Compare is the matched A/B**: momentary, level-matched within 0.2 dB, keeping leveling, the turn-down, correction and compensation in.

## 10. Adaptivity engine + pre-analysis (LD-5, LD-6)

> **DESIGN — mostly not built.** The one shipped piece is load-time **track loudness analysis** (`TrackLoudnessKit`, Sprint EQ): the current and next track are decoded a second time off the audio path into a K-weighted spectral profile that drives the loudness-neutral EQ gain (§2.5). Today the "±12 dB trust clamp" is three independent ±12s that nobody adds — the EQ points (`EQEditKit/EQBands.swift:26`), −ΔL (`Loudness/TrackLoudnessGain.cpp:13-14, 120`) and the AGC's makeup (`Loudness/LoudnessModule.h:55-56`, removed) — before a true-peak-only limiter. **Say it plainly: the true-peak net protects the signal, not the ear** — a heavily boosted, net-held signal has the same peak as the untouched file and can be far louder on average. What protects hearing today is the taste layer's loudness neutrality (decision 26), a turn-down-only Master Gain and the headphones' own volume; what will is the sum clamp. The loudness clamps in the table (short-term, integrated, cumulative, the confirmation gate, low-confidence magnitude) **stay design** for the Arbiter.

The Arbiter (when built) enforces these gain-safety clamps on all contributor/user-gain output to prevent hearing damage:

| Parameter | Bound | Hard Clamp | Notes |
|---|---|---|---|
| **Per-band boost** | +10 dB | +12 dB | Frequency-variable: sub-bass +8 dB, bass/mid/air +10 dB, 3–5 kHz (hearing-hazard zone) +8 dB |
| **Per-band cut** | −12 dB | −15 dB | Cuts are not hearing-risk; caps prevent artifacts (notch-filter effect) |
| **Short-term loudness (3 s, BS.1770)** | −5 LUFS | Hard via re-sum scalar | Catches sustained boosts the true-peak limiter misses |
| **Integrated session loudness** | −9 LUFS (gated) | Soft clamp + transparency | Prevents accumulated gain requests from ratcheting loudness up |
| **Cumulative gain-driven loudness change** | +12 dB | Hard; proportional scaling | Six bands at +10 dB each ≠ +10 dB overall; cap prevents surprise volume spikes |
| **Confirmation gate trigger** | +8 dB per band | UX gate | Shows magnitude explicitly; suggests volume control as primary lever |
| **Low-confidence magnitude** | ±3 dB | Conservative default | Applied when confidence < 0.5; prevents hallucinated large gains |

**Rationale:** A +10 dB bass boost at 75 dBSPL → 85 dBSPL (NIOSH 8-hour limit for hearing-hazard frequencies). The true-peak limiter catches peaks but not sustained energy boosts; the short-term LUFS ceiling handles this. Tighter cap at 3–5 kHz (+8 dB) because this is the ear's most vulnerable frequency range. Confirmation gate at +8 dB makes large boosts visible to the user, who can use the volume control (the primary lever for safe listening) instead. Phase 0 SPIKE-HEARING-SAFETY-VALIDATION will measure whether users feel +10 dB is appropriately responsive to a large-boost request or too conservative. (Sources: NIOSH criteria; WHO-ITU H.870; audio-dsp-agent analysis grounded in ISO 226 / Fletcher–Munson physics.)

## 14. Cross-cutting

- **Param bus:** Arbiter→Realizer publishes a **per-stem TargetState→finished-coeffs snapshot** atomically (double/triple-buffer); RT reads latest + ramps (≥50 ms). Events (load IR/stems) via SPSC. Meters/FFT/loudness up via seqlock/ring, polled by a UI timer (≥30 fps for the analyzer; ≥2 Hz for the transparency view).
- **IR hot-swap (convolver lifetime):** At session init, exactly **2 pre-allocated `ConvolverSlot` objects** (generalize to N for future per-profile IR caching). Each slot holds the full BRIR convolution engine. The active slot index is an `std::atomic<uint8_t>` published by the non-RT Realizer with `memory_order_release`, read by the RT render thread with `memory_order_acquire` (once per buffer, held for the duration). **When the Realizer must swap IRs** (Reimagine knob change, device switch), it: (1) loads new IR data into the inactive slot (entirely off-RT); (2) waits for the current crossfade to complete (≥50 ms, see below); (3) atomically stores the new active slot index. The crossfade window is strictly longer than one render callback, so the previously active slot is guaranteed idle by the time the Realizer reuses it. **No convolver slot is ever freed** — object lifetime is managed entirely by the non-RT plane. Overlapping swaps are serialized: the Realizer queues up to 1 pending swap; intermediate requests are dropped (last-writer-wins).
- **Crossfade during IR swap:** Triggered by Reimagine knob or device switch. The **crossfade duration is tied to the parameter ramp (≥50 ms)**; both old and new IRs run for this window, crossfaded on the output. The crossfade masks any discontinuity between slots.
- **Threading / Audio Workgroups:** with up to **6 stems × full chains × BRIR convolution**, the render uses **`os_workgroup`** to fan parallel per-stem work across cores while holding the per-buffer deadline.
- **Privacy (NFR-PRIV):** mic → SPL scalar only, never transmitted; graceful offline fallback (LD-11).
- **Quality floor (NFR-QUAL):** the **bit-transparent path = intensity 0 with the EQ flat or off** (kernel path P0 since Sprint EQ; verified by a memcmp-equal bypass; a *kernel-bypass* within the Enhanced graph). Distinct from the shipped **Pure Mode HAL path**, which is bit-perfect by bypassing the whole AVAudioEngine graph + DSP at the device boundary (§2.5). THD+N budget tracked across the chain; validated at 44.1/48/88.2/96 kHz.
- **Persistence:** device↔profile binding; cached stems + pre-analysis. *(Shipped today: the listener's settings, the EQ's per-output memory, the library and the queue — §2.5 "What persists".)*

## 15. Performance & feasibility budget ⚠ (key review target)

The ambition (6 stems × per-stem EQ/dynamics/**BRIR convolution** + masking) is the **chief feasibility risk**. Mitigations: heavy work is **off-RT** (separation, FIR/BRIR design, masking analysis — all pre-computed/cached); the RT kernel runs **fixed, partitioned convolutions** parallelized via **Audio Workgroups**; **QualityProfile** scales partition sizes / stem count / convolution length under battery/thermal. **The raised hardware floor + sole-occupancy posture (LD-18) materially reduce this risk** vs. an 8 GB fanless Air — an M1 Pro has more performance cores, a fan, and ample RAM, and the app need not share the machine. The **shared-late-reverb decomposition** (one room tail + cheap per-stem placement filters) is now the **planned approach** (v0.3, §6/§7) — it cuts the dominant convolution cost ~6× (turns "6 long convolutions" into "1 long + 6 cheap"). **Hardware context:** the shipping generation sits well above the floor — M4 (38-TOPS NE, ~120 GB/s) → M4 Pro/Max (10–12 P-cores, 273–546 GB/s, 64–128 GB) and M5 (per-GPU-core neural accelerators, ~4× M4 GPU-AI compute, 153 GB/s) — i.e. ~3–4× the floor for this AI/convolution work, so on shipping hardware the risk is **Low** and the spike is for tuning QualityProfile caps, not go/no-go. **Open:** measured per-stem RT cost, total memory for 6 cached stems + BRIR kernels, and the worst-case render budget on **the M1 Pro / 16 GB floor** (spike before Phase 1.5 — see backlog).
